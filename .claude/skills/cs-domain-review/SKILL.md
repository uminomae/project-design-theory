# 創造とは：一つの分野を回す

計画と規約の正本は `docs/cs-review/README.md`。このスキルは、その「調査の手順（一つの分野）」を一分野ぶん回す順番だけを書く。食い違ったら README を正とし、このスキルを直す。

## 役

- 司令塔は、このスキルを使う親のセッション（Fable 5.1）。材料は自分で読み込まず、エージェントの報告を受け取って、確かめ、仕上げる。
- 調べるのは Opus のエージェント（Agent ツールの `model: "opus"`・`run_in_background: true`）。同時に走らせるのは 2〜3 まで。待つ間に、次の分野の割り振りや、済んだ分野の仕上げを進める。

## 始める前に（セッションで一度）

1. CLAUDE.md、`docs/rules/` の四本、本体の checkout の `.cache/session/` のその日と前の日の記録、`docs/cs-review/README.md`・`history.md` を読む。
2. `git log --oneline -20 develop` で、ほかのセッションが cs・wiki・`docs/rules/`・`docs/cs-review/` を直していないかを見る。
3. Issue #73（cs の全体レビュー）のチェックリストで、次の分野を決める。README の「判断が要ること」に答えが出ていないものがあっても、照合は進める。

## 一つの分野の順番

1. **頼む**：`docs/cs-review/prompts.md` の「1. 内容の照合」を、分野の番号・slug・作業場所（W）・領域ごとの注意で埋め、Opus のエージェントに頼む。slug は `ls ~/dev/pd/pjdhiro/assets/creation/domains/ja/md/` で確かめる。論は、すでに集めた原典（台帳・手元の PDF・精読ノート）をベースにする。読める原典が 10 に届かない分野（README「調査の手順」の表）は、さらに探すよう頼む文に書く。
2. **確かめ直す**：報告が届いたら、要の点を二つ三つ自分で確かめる（DOI を Crossref で引く、原典か精読ノートの引用を一つ開く、今の報告の行を一つ開く）。報告をうのみにしない。
   - エージェントが新しく見つけた原典は、司令塔が `cs/knowledge/raw/manifest.md` に行を足し（公開）、PDF は手元の `cs/knowledge/raw/` に置く（git の外）。足す前に、PDF の先頭が %PDF か、1 ページ目の書誌が合うかを見る。
3. **仕上げる**：エージェントが書いた `cs/evidence/evidence-Dxx-*.md` を読み、次を見て直す。
   - 中心の問い：論ごとに、対立・衝突・統合・新たな安定（または至らない形）が一行になっているか。悪い統合も統合、片方の勝利は波に留まるか場に戻る（README「中心の問い」）。
   - 一次情報：各論に確かめ先（URL・DOI）と読んだ頁があるか。照合の状態は `sources.md` §3 の四つか。
   - 文：`writing.md`（教科書のような普通の文・演出しない・断定しない）、冒頭に文責が Claude。旧い語（Phase・温度帯・安全弁・verified など）が無いか。手元の絶対パスが無いか。
   - 判断が要るもの：stance.md で答えを予想し、答えが出るものは決めて書く。出ないものだけを残す。
4. **UI**：この分野の新しい md を、cs のトップの「30 領域調査報告」の画面から、今の見た目で読めるようにする（今は `cs/src/reports/data.js` が pjdhiro の repo の `assets/creation/` を読んでいる。済んだ分野だけ新しい md を読む形にする）。3001 で、PC とスマートフォンの幅（375px）で開いて確かめる。
5. **機械的な誤りを直す**：この分野で見つかった DOI・書誌・切れたリンクの誤りは、出どころ（wiki の精読ノートなど）まで直す（README「レビューの決まり」）。pjdhiro の repo の今の報告は、README の判断 2 のとおり、決まるまで触らない。
6. **入れる**：`bash scripts/check.sh` を走らせ、commit（末尾は CLAUDE.md のとおり）。develop へすぐに取り込み、push する。`.claude/` を含む取り込みはサンドボックスの外で行う（corrections 型 K）。main への公開は、最初の分野だけ pjdhiro に 3001 か確かめ用のページで見せてから。二つ目からは、確かめが済んでいれば送る。
7. **記録する**：Issue #73 に、その分野の要約（論の数・本文照合済の数・高い誤り・判断が要るもの）をコメントし、チェックを付ける。`.cache/session/` のセッションの記録に足す。
8. 最初の 5 分野が済んだら、記録の形を一度だけ pjdhiro に見せる（README「区切りと終わり」）。
9. **確かめ用のページを更新する**：Issue #73 や対話で計画が変わったら、pjdhiro の確かめ用のページ（アーティファクト「創造とは レビュー計画」。Artifact ツールの list で題名から探す。URL は非公開なので repo に書かない）を、その都度今の状態に合わせて publish し直す（pjdhiro 2026-11-08「随時更新してください。issue や対話によって変更になったものを」）。

## セッションの終わりに

CLAUDE.md の「セッションの終わりに」を行う。このスキルで回して食い違った所や足りなかった所は、README・prompts.md・このスキルを直す。
