## 読む場所

- 本体の checkout：`{本体の checkout のパス}`（枝 develop・始めの commit {commit}）。**ここを読む。書かない。**

## してはいけないこと

- repo のファイルを直さない。commit・push・merge・checkout・stash をしない。ほかのセッションが同じ checkout で動いている。
- 生成のスクリプト（build・compile・generate）を走らせない。走らせてよいのは、読むだけの点検（`scripts/check.sh`・`pd/scripts/*-lint.mjs`・`*-check.mjs`・`*-audit.mjs`・`reader-llm-comprehension-test.mjs` など。出力先があるものは、下の報告の場所の下に向ける）。走らせて作業ツリーに差分が出たら、すぐ報告に書く。
- 外へ出る命令：書誌の照合（Crossref・doi.org）と、原典の頁を開くことは、してよい。`gh` は読むだけ（Issue や PR を読む）。書き込み（コメント・Issue の作成・push）はしない。サンドボックスの外で走らせたものは、命令を報告に書く。
- pjdhiro（この repo の編集者）に質問しない。判断が要るものは、報告に「判断が要る」と書き、`docs/rules/stance.md` から予想した答えを添える。
- ほかのエージェントを起こさない。

## 指摘の形

一件ごとに次を書く。行番号はずれるので、見出しと鍵の文（grep で見つかる短い引用）で場所を示す。

- 場所（ファイルと、見出しか鍵の文）
- 何が問題か（一、二文）
- 根拠（どの規約のどの行に当たるか・何を開いて確かめたか・実行した命令と結果）
- 重さ：高＝誤り・捏造・帰属違い・数字や書誌の食い違い・規約どうしの矛盾で Claude が誤った操作をしうるもの・公開してはいけないものの混入・仕組みが実際には動いていないこと／中＝言い過ぎ・定義のずれ・古くなった記述・重複・肥大／低＝文体・表示
- 確かめた度合い：「開いて確かめた」「実行して確かめた」「推測」を分ける。推測は推測と書く。名前や置き場だけで重さを付けない。中身を開いてから付ける
- 直し方の案（高・中だけ。一、二文）
- 判断が要るか（要るなら、stance.md から予想した pjdhiro の答え）

「0 件」「無い」「動いていない」と書く前に、もう一つ別の方法で数え直す（型 K）。
