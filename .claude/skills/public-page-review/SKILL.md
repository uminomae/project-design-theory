# 公開ページの点検

公開ページを作る・直すたびに通す一巡。項目は、これまで公開ページで実際に起きた誤りから取った。各行の括弧は、起きた commit か Issue。どこを見ればよいかは、過去にどこが壊れたかで決める（pjdhiro 2026-11-10「公開ページのレビュー時に気をつけることを溜めていってね。…コミット履歴を見ればどこをチェックすべきかがわかると思う。…公開ページを作る際に、必ずチェックしたい」）。

ほかの点検との分け方：

- `docs/PUBLISH-CHECK.md`：公開してはいけないもの（手元の語・パス・鍵）の混入。pre-commit で自動に走る。
- `docs/rules/review.md`：読み物一本を main に出す前の念入りなレビュー（エージェントを並べる）。
- `.claude/skills/weekly-review/`：repo の全体を一巡するレビュー。
- **ここ**：公開ページを作る・直すたびに、司令塔か作業するセッションが自分で通す最低限の表。上の三つの代わりにはならない。念入りなレビューを回すときも、この表は回す。

## いつ使うか

1. 公開ページ（`pd/reader/`・`pd/index.html`・`pd/wiki/`・`cs/`・`as/`・`ks/` の公開する部分・公開する PDF）を作った・直したとき。commit の前。
2. `git push origin develop:main` の前（`bash scripts/publish-main.sh develop` で一緒に出る commit を見たあと、その commit が触った公開ページに）。
3. pjdhiro に公開ページの誤りを指摘されたとき、fix の commit を書いたとき：直したうえで、下の「表を育てる」を行う。

全部の行を毎回見るのでなく、触ったページの種類に当たる節を見る。ただし §1 と §2 は、どの公開ページでも毎回通す。

## 仕組みで止める（pre-commit）

`.githooks/pre-commit` が、公開ページ（サイトに出るファイルと読み物の正本 `READER-*.md`。道具・テスト・wiki の `log.md` と `health/` は外す）を含む commit を、表を通した印が無ければ止める。

1. `bash scripts/public-page-review.sh`：commit しようとしている公開ページと、見る節を出す。
2. 出た節を、この表で通す。当たったものを直す。
3. `bash scripts/public-page-review.sh --done`：今の index に印を置く。そのあと commit する。

印は worktree ごとで、index の tree の番号と時刻が入る。印のあとに `git add` で中身を変えた・60 分を超えたときは止まるので、通し直す。merge の commit には走らないので、develop への取り込みは止めない。印は「走らせた」ことしか確かめられない。表を読まずに `--done` を走らせない。フックは本体の checkout の `.githooks/` の版が動き、道具は commit をする worktree の版が動く（道具の無い古い worktree では止まらない。`bash scripts/sync-develop.sh` で揃える）。`--no-verify` とクラウドのセッションの commit では走らない（`docs/PUBLISH-CHECK.md`「ここは仕組みで止まらない」）。

## 表を育てる（常に更新する）

この表は、公開ページで誤りが見つかるたびに育てる。

1. **公開ページを直したとき・指摘されたとき**、同じ作業で、当たる節に行を足すか、既にある行に commit を足す。行には、何を見るかと、起きた commit（または Issue・日付）を書く。同じ誤りが二度目なら、行を書き足すのでなく、機械で止める形（`scripts/check.sh` の検査・`check-public-notices.mjs` の `--strict`）に移せないかを見て、移したら §1 に書き、行には「機械が見る」と書く（`corrections.md` の「繰り返し」と同じ考え）。
2. **履歴から拾い直すとき**（週のまとめのレビュー・このスキルを使い始めるとき）、下の「履歴を見た所」から先の fix の commit を読む：

   ```bash
   git log --no-merges --pretty='%h %s' 77a64bc..develop | grep -E '^[0-9a-f]+ fix'
   ```

   公開ページに当たるものを拾い、行を足したら「履歴を見た所」を進める。
3. 公開ページに関わらない直し（規約・道具・記録の形だけ）は足さない。それは `corrections.md`・`docs/TESTING.md` の側。
