# 目指すもの
物理や数学のイメージを持ちながら、幻想的で、抽象的で、意味深なもの。
見た人が「何かの式から生まれた形だ」と感じるが、何の絵かは言い当てられない、くらいの抽象度にしてください。

# ページが扱っていること（形に込めたい意味）
ページの問いは「私は何に駆られてプロジェクトを行うのか」。人や物事を動かしている源（駆動源）を、仮に Love と呼んで探っています。次の四つを、図解ではなく、形と動きの質感として込めてください。

1. 見えない源：源そのものは描かない。周りの無数の軌跡の曲がり方・混み方・速さだけで、そこに何かがあると分かる。重力が、周りのものの動き方で書かれてきたように。
2. 二つで一つ：分かれて見えるものが、別の見方では一つの流れにつながっている。切り離されていない。
3. 波と渦：大きな場のゆらぎの中に、ひととき渦（形）が立ち、また溶けて場に戻る。
4. 制御しきれない：決まった式で動いているのに、先が読み切れず、同じ形に二度は戻らない。

曲がった空間の測地線の流れ・ベクトル場の流線・ストレンジアトラクター（Aizawa・Thomas・Lorenz など）・結合振動子の同期（蔵本モデル）・トーラスの上の流れ・波の干渉。

- 背景は画面いっぱいに固定され、その上の中央に、白いすりガラスの読書欄（幅は最大 860px、白 75% ＋ぼかし）が重なります。広い画面では左右の余白に背景がはっきり見え、スマートフォンではほぼ全部がすりガラスの奥になります。

- ページはとても長い読み物です（25 章ほど）。前半のテーマは「駆動源（見えない源）」、後半のテーマは「開発（意図して進めるものも、意図しないまま育つもの・変わっていくものも）」。スクロールの割合（0〜1）に合わせて、景色をゆっくり連続的に変えてください。急に切り替わる段は作らないでください。

# 技術の要件（必ず守る）
- three.js r0.183.0 を ES Module で読む：
  https://cdn.jsdelivr.net/npm/three@0.183.0/build/three.module.js
  （addons が要るときは https://cdn.jsdelivr.net/npm/three@0.183.0/examples/jsm/ から）
- 描画は WebGLRenderer だけ。WebGPU は使わない（Safari 18 / iOS 18 以前でも映ること）。
- 既にある <div id="webgl-container"></div>（position: fixed で画面全体、pointer-events: none、本文の後ろ）の中に canvas を一つ入れる。ほかの DOM・UI・GUI は作らない。
- 地の色は自分で塗る（不透明）。
- スクロール：window のスクロールの割合（0〜1）を読み、requestAnimationFrame の中で慣性を付けて追う（current += (target - current) * 0.05 のように）。
- 指の追従は、細かいポインタ（matchMedia('(pointer: fine)')）のときだけ、ごく軽く。window でイベントを取る。
- 速さ：MacBook Air（M1）の全画面で 60fps。renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5))。スマートフォン（Math.min(screen.width, screen.height) < 700）では、粒や線の数を半分くらいに。画素ごとに 3D ノイズを何回も重ねる体積のレイマーチはしない。ブルームや残像などの後処理は使ってよいが、軽く。
- prefers-reduced-motion のときは、止めた一枚を描いて止める。タブが隠れたら止め（visibilitychange）、戻ったら再開。画面の大きさが変わったら合わせる。
- 数値の安全：pow の底を負にしない、0 で割らない、NaN や無限大を出さない（残像を使うと一度の NaN が画面に残り続けるので）。fract(sin(x) * 43758.5453) 型の乱数は使わず、粒ごとの乱数は JS で作って attribute で渡す（iPhone の GPU で値が崩れるため）。
- 片付け用に export function cleanup() を用意する（requestAnimationFrame の停止・dispose・リスナーの解除）。
- コードの頭に、日本語の注記で、どの数式から何の形を作ったか、その形に上の四つのどれを込めたかを書く。

## 創造とはの背景（`cs/?graphic=i`）の分析（2026-11-10）

pjdhiro「gemini でも全く違う。cs/?graphic=i を分析して。無数のスパイラルを描く光る繊細な線が良いのかも」。コードは `cs/src/scene-intent.js`（値は `cs/src/config/params.js` の `intentConsciousnessParams`）。

- **線を描いていない。** 画面いっぱいの板一枚のシェーダー。画素ごとに奥へ光線を進め（デスクトップ 52 歩・スマートフォン 34 歩）、空間に置いた数式の膜の上だけを光らせて、手前から半透明に積み重ねる（体積のレイマーチ）。点も線も置いていない。Gemini の三つは点を置いて揺らしただけなので、線が生まれなかった。
- **膜はジャイロイド**（三重周期極小曲面 sin x·cos y + sin y·cos z + sin z·cos x = 0）。値が 0 に近いごく薄い層（厚み 0.095〜0.17）だけを光らせる。二つの周波数を重ねる（0.74 と 0.26）。
- **無数のらせんになる理由：** 空間を軸に沿ってねじる（奥行きで回す角度 0.24、時間で 0.12）、軸の方向へ流す（0.21）、軸を sin・cos でうねらせる。半径 2.44 の管の中に膜を閉じ込め、カメラはその管を覗く向きにある。だから、ねじれた膜が渦を巻くトンネルとして見える。
- **線が極細に見える理由（移して確かめた）：** 光線の歩幅がほぼ一定（0.084〜0.215）なので、カメラから同じ距離の球面ごとに膜を切った断面が、細い弧になって何重にも並ぶ。計算の粗さが作る模様が、美しさの芯になっている。コードには最初の一歩を画素ごとにずらす乱数（0〜0.08）があるが、時刻の値が大きいため、ほぼ効いていないと見る。移した版でずらしを効かせると線がざらつき、ずらしを無くすと cs と同じくっきりした輪になった（`love-membrane.js`・2026-11-10）。管の軸に沿って覗く向き（yaw ≈ −π/2）でいちばん美しく、斜めに回ると、ざらついた縞に変わる。
- **光の質：** 前から積む重ね方（加算でない）。積んだ色を 2.04 乗して暗いところを沈め、重なったところだけを浮かせ、1 − exp(−2.45·色) で白飛びさせずに柔らかく飽和させる。色は管の手前から奥へ、冷たい青（0.12, 0.2, 0.68）から暖かい白へ。真ん中の「門」に金（1.3, 0.9, 0.2）を足すので、中心が金色に光る。
- **動き：** 膜が流れ、カメラが自動でゆっくり回る（向き 220°・周期 480 秒）。8 秒の呼吸で膜の厚みと明るさが脈打つ。後処理（ぼかし・ブルーム）は使っていない。
- **進む動きを付けるときの注意（2026-11-10）：** 輪の線は、カメラから一定の距離ごとに膜を切った断面なので、カメラに貼りついている。膜の場だけを送って奥へ進めても、輪は同じ画面の位置に出続け、同じ所にいるように見える（pjdhiro「実は同じ位置にいるように見える」）。切る距離の起点を、進んだ距離に合わせてずらし、輪を場に固定する案（uPhase）と、場に固定した明るい層（uGap・uLayer）を試したが、pjdhiro「だめ。一つ前のやつに戻して」で戻した（9728844 → 13a4002）。
