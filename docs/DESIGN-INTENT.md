## 1. 概要

pjdhiro の見方と判断の基準（暗黙知）を形式化し、AI が読み込んで実行できる形で配布する。役割は、思考・心理・文章・組織の脆弱性を検出するバグチェッカー。

## 2. 目的

| ID | 目的 |
|---|---|
| G1 | 暗黙知を形式化する。LLM が pjdhiro と同じように判断できる状態を目標にする |
| G2 | 文章・論・施策に含まれる誤解（バグ）の発生源と症状を検出する |
| G3 | 検出の結果を通じて、読者の発達段階の移行を支え、誤解そのものを減らす |
| G4 | 人類の man（説明書）のようなものを整理していく。概念・式・論を関数として扱い、何をするか・前提（省略されている既定値）・例・使い所・注意・関連を、LLM が学習しやすい形で書く（2026-11-26） |

G3 の想定される波及：教育の変化、組織運営（ティール組織など）の容易化、犯罪の減少。いずれも見込みで、測定はしていない。

## 3. 目的としないこと

| ID | 目的としないこと |
|---|---|
| N1 | 新しいアイディアの提供 |
| N2 | 真理の論証。全体はアブダクション（仮説推論）として置く |
| N3 | 単独での正しさの保証。一つのチェッカーとして、ほかのチェッカーと併用する前提 |
| N4 | 人間の読者を第一の利用者とすること。第一の利用者は AI |

## 4. 前提

| ID | 前提 |
|---|---|
| A1 | 論拠は体験を先に置く。理論は、体験の中で現象として確認できるものを採用し、骨格は後続の論で修正する |
| A2 | どの論も対象の一面である（群盲象）。この repo も一面 |
| A3 | 現象の記述は回転の構造で行う。人間の認知は複素数・三次元の回転として現象を捉えるため、この構造の類似は広く当てはまる。これは対象の性質であると同時に、観測する側（数学という道具と認知）の仕様でもある。仕様として受け入れ、それに合わせて記述する |
| A4 | 人間が直接扱えるのは三次元（四元数）まで。それより高い次元は AI が扱う |

## 5. 構成

### 5.1 層

| 層 | 役割 | 実装 |
|---|---|---|
| L1 現象 | 二次元・三次元の現象を客観の側から記述する | 創造とは（`cs/`、創造の五段階）、読み物（重力と愛・ジュリア集合） |
| L2 心模様 | 同じ現象を、主観の側から記述する | 意識とは（`as/`、生存と信頼の二軸）、欠損駆動思考（`ks/`） |
| L3 翻訳テーブル | 発達段階 × 防衛 → バグの発生源と症状 | 読み物（発達段階と心理的防衛機制・心理的安全性とは・脆弱性から全体を知る） |
| L4 高次元化 | L3 を高い次元に拡張する（目標は八元数） | 未実装 |

### 5.2 検出の仕組み

| 構成要素 | 内容 | 実装 |
|---|---|---|
| ルール | 根本の規則。新しい対象にも適用できる | 創造の五段階、意識の二軸、ジュリア集合の当てはめ |
| 事例の台帳 | 既知の誤解の一覧。シグネチャに相当する | `docs/tools/kokoro-scan/ruler.md` の「よくある誤解（台帳）」 |
| 多面的な適用 | 一つの対象に複数のルールを当てる | 未定義 |
| 実行できる道具 | 対象を渡すと結果を返す | 心の脆弱性スキャン（`docs/tools/kokoro-scan/`）、ものの見方の広さスクリーナー（`pd/reader/stages-screener.html`） |

### 5.3 モジュール

独立ページをモジュール（関数）として扱う。Love駆動開発は、複数のモジュールを呼び出すパッケージ。仕様は `docs/LOVE-DRIVEN-DEV-SPEC.md`。

独立ページと解釈したページには、本文（対話の形・追体験の流れ）をそのまま残し、ページの終わりか機械向けの層に、man の形の要約を置く（G4）。一つの HTML に、複数の関数の man があってよい。手本は「オイラーの等式が、たたんだもの」の章「exp の説明書に、たたまれていたものを書き足す」（既にある説明書に、ページで開いたものを色で足した形）。形の細部（見出しの並び・機械向けの層の書式）は未定（§9）。

## 6. 配布

### 6.1 出力の層

| 層 | 利用者 | 作成 | 確認 |
|---|---|---|---|
| md（規約・記録・照合） | LLM | Claude | pjdhiro の判断を反映 |
| 公開ページ | 人 | Claude | pjdhiro が確認する |
| 高校生向けの解説 | 人 | Claude | なし（公開ページから生成） |

pjdhiro の確認が入るのは公開ページまで。それ以降の層は AI が生成する。読者が手元の LLM で要約する使い方も想定する。

### 6.2 導入

OSS として配布する（ライセンスは MIT。`LICENSE`）。LLM には repo を取得させ、根の `README.md` の手順で読ませる。将来、LLM の利用者ごとの設定（カスタマイズ）の機能が増えた場合は、この repo をその設定に組み込む形を想定する。

### 6.3 要約による欠落への対処

要約は、検出の要になる衝突（二面性・逆説）を落としやすい。この欠落は制御できない。緩和策として、ページの meta 情報に落としたくない要点を置く。

## 7. 名乗りと検証

| 項目 | 方針 |
|---|---|
| 名乗り | 全体をアブダクション（仮説推論）、素朴体験論として名乗る |
| 検証 | 演繹と帰納は、一つの見方として徹底して検証したものとして置く（原典の照合・反証・盲検） |
| 狙い | 正解を求める発達段階の読者に、正解を求める方法そのものを示す |

## 8. 既知の制約

| ID | 制約 |
|---|---|
| K1 | 体験に合うものが集まる偏りがある。論拠は分野を問わず広く集める |
| K2 | ルールの根が共通（体験と回転の構造）のため、複数のルールの結果は独立した判定にならない |
| K3 | 創造の五段階の盲検では、縁の段が広く当てはまりすぎる結果が出ている（`cs/evidence/falsification/blind-test-5stage/RESULTS.md`） |
| K4 | 検出の誤検知の率は測っていない |
| K5 | 論拠は pjdhiro 一人の体験（N=1） |
