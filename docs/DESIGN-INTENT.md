# この repo の狙いと設計

pjdhiro が 2026-11-24 の対話で話した、この repo の狙いと設計を、Claude が整理したもの。見方の正本は `docs/rules/stance.md` の 1-4（同じ日の行）にあり、何への答えだったかと原文は `docs/rules/stance-history.md` の 1-4 にある。見出しと並べ方は Claude の整理で、本人の言葉ではない。本人の言葉と食い違ったら、stance.md を正とする。

## 一言で

この repo は、pjdhiro の見方と判断（暗黙知）を形式化し、AI が読み込んで使える一つのバグチェッカーとして置くもの。

## 1. 狙い

- 暗黙知の形式化。基本的な作業だが、AI がないと大変だった。これからは楽になる。
- その先で、教育も変わる。発達段階を上げ、誤解そのものを減らすことで、ティール組織なども作りやすくなる。犯罪も減るかもしれない（本人の見立て）。
- AI 社会で真っ先に取り組むのは、過去の清算。コストを理由に取り繕ってきたものが、AI によって見つかっていく。だから、この repo の優先は、デバッグの方法を載せていること。新しいアイディアは要らない。

## 2. 土台にしている見方

- 体験が先。基礎にする理論は、自分に合うかどうかで選ぶ。読んで、試して、残す。体験の中で現象としてあるものは、評判が悪くても残し、骨格はあとの論者で削る。基礎があれば、応用は本人がやる。
- 群盲象。どの論も一面で、この repo も一面。
- 構造の類似。要は回転。意識とはの仮説は、闘争と逃避、好きと嫌いの二軸（生存と信頼の信号）。創造とはは、四元数による三次元の回転で、反対側に回転子がいる。
- 認知の仕様。構造の類似が、複素数の構造に乗ってほぼ全てに当てはまるのは、人の認知がそうだから。そこがボトルネックで、それを通して得られるものが最も細かい分析になる可能性がある。壁に当たると停滞する。そういうものと受容して、仕様に合わせて記述する。ハックでなく、丁寧な設計。回転は本質ではなく本質の現れだが、同時に、数学という道具と三次元の制約の中の認知が、現象をそう見せている。それ以外は、どうせ理解に苦しむので実用的でない。

## 3. 中身の層

本人の言葉は「pdt repo は足場として、二次元・三次元の世界の現象を、客観と主観で扱う。それを心模様として、どう素朴に感じながら生きているのか。そこに発達段階と防衛を重ねて、バグの発生源と症状という翻訳のテーブルを作っている。それを高次元にするだけ」。層の分け方と置き場の対応は Claude の整理。

| 層 | 中身 | 主な置き場 |
|---|---|---|
| 現象（客観） | 二次元・三次元の世界で起きること | 創造とは（`cs/`）、読み物の重力と愛・ジュリア集合 |
| 心模様（主観） | それを、素朴にどう感じながら生きているか | 意識とは（`as/`）、欠損駆動思考（`ks/`） |
| 翻訳のテーブル | 発達段階 × 防衛 → バグの発生源と症状 | 読み物の発達段階と心理的防衛機制・心理的安全性・脆弱性から全体を知る |
| 高次元化 | テーブルを高い次元にする | これから |

人が分析できるのは、四元数で三次元までが限界かもしれない。ただ AI がいるので、次元を上げることは、多変量解析に放り込むように、ふつうの方法になっていく。心の解明というより、実用的な分析を AI と八元数で行うのが、本人の到達点。

## 4. 問い

創造とはだけでもそこそこ良く、反対側を場で意識していくことも実用的だが、それも一部。問いは、なぜ衝突してまでも創造してしまうのか。駆動源の問いで、Love駆動開発がこれを扱う。

クリエイター・クリエイティブ・創造的な仕事のような言葉は、過剰な「良い」で自滅する。衝突がない。

## 5. ソフトとしての働き

- デバッグ文・テストコード・ウイルス検知プログラムのような働きを持たせる。
- 根本のルールを、ジュリア集合のように用意しておく（創造の五段階・意識の二軸・ジュリア集合の当てはめ）。事例（よくある誤解）も集める。一つのテストコードでなく、多面的に当てるため。
- 体験にしっくりくるものだけが集まる偏りはあるが、論拠は全人類のものから集める。pjdhiro という一つのバグチェッカーとして使ってもらい、ほかのチェッカーも並べて使ってもらう。
- 検知の信頼性の評価は、セキュリティ会社の評価のように難しいが、その分析も AI がする。
- いま動くもの：心の脆弱性スキャン（`docs/tools/kokoro-scan/`）、ものの見方の広さスクリーナー（`pd/reader/stages-screener.html`）。

## 6. 届け方

- AI の時代に、人に読まれるとは思っていない。AI が読むので、最初から AI 用に書く。インストールしたら機能するよう、UI まで配慮しておく。プログラマなら誰でもする、同じ発想。
- 読み手の層は三つ。本人の確かめが入るまでを組めば、そこから先は AI が量産する。

| 層 | 読む相手 | 書く人 |
|---|---|---|
| md（規約・記録・照合） | LLM | Claude（本人の判断が入る） |
| 公開ページ | 人 | Claude。本人の確かめが入る |
| 高校生向けの解説 | 高校生 | Claude |

- 読者が手元で要約させればすむ。「とりあえずググって」のように、「とりあえず要約させて」の流れになっていく。
- 要約で縁（衝突）が落ちることはコントロールできない。meta 情報に入れておくことはできる。LLM がユーザーに合わせて縁を作る進化も考えられ、そのときに、この repo をインストールしてもらう。OSS の考え方。独立ページは関数で、Love駆動開発は複数のモジュールを一度に呼び出すパッケージ。

## 7. 名乗り

アブダクションと言い張りながら、演繹と帰納は、一つの見方として徹底的に検証されたものであるかのように置く。それでも推論に過ぎないと言い張る。正解を求める発達段階の人に、正解を求める方法を見せている。期待しているのは、パースがどうせ推論に過ぎないとしたものが、どれほど強力か。

## 8. まだ開いている所

同じ対話で Claude が出し、本人が答えを置いていないもの。決めたことではない。

- ジュリア集合の当てはめにも、創造の五段階と同じ盲検をかける（当てはまらないはずの対照を先に決める）。
- 心の脆弱性スキャンの誤検知。脆弱性の無いはずの文章を「検出なし」と返せるか。
- 根の同じ物差しを並べても、独立した票にならない。外の論から借りた物差し（野中を批判的に読む問い・新田の悪さと弱さ・ポパーの反証の基準 など）も混ぜる。
- 八元数の七つの軸に何を当て、どんなデータを入れるか。
- 要約されても落ちない一文を、ページの meta 情報にどう置くか。
- モジュールとして配るときの、入出力の約束・版・改変されたときの見分け。
