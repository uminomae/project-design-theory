## 1. 概要

Love駆動開発は、プロジェクト（事業・人生・家族・社会を含む）の駆動源を見る見方を、複数のモジュールを呼び出すパッケージとしてまとめたもの。対象の文章・論・施策を受け取り、駆動源の分析と、誤解（バグ）の検出、対処の手がかりを返す。

- 本体の正本：`pd/knowledge/research/love-driven-dev/READER-love-driven-dev.md`
- 公開ページ：<https://uminomae.github.io/project-design-theory/reader/love-driven-dev.html>

## 2. 機能

| ID | 機能 | 内容 |
|---|---|---|
| F1 | 駆動源の分析 | 対象が何によって動いているか（何に駆られているか）を記述する |
| F2 | 防衛の検出 | 良い側だけで書かれた言葉（共感・信頼・愛 など）の裏にある、心を守る働き（防衛）の抜けを検出する |
| F3 | 段階による反転の検出 | 同じ言葉が、受け取る人の発達段階によって逆の向きに働く箇所を検出する |
| F4 | 取り違えの検出 | 近い心の働き（自己の対象化と他者視点取得 など）の取り違えを検出する |
| F5 | 条件の欠落の検出 | 規範が成り立つ条件（雇用の形・時代 など）が書かれていない箇所を検出する |
| F6 | 対処の手がかり | 効く条件と、補える所を示す |

## 6. 動作の規約

| ID | 規約 |
|---|---|
| R1 | Love駆動開発は仮説（pjdhiro の素朴体験論）として扱う。対象の正誤を裁く基準にしない。優れたものとして勧めない |
| R2 | 対象も Love駆動開発も一面として扱う。違いより先に共通する所を書く。「A ではなく B」と切らない。善悪の判断を持ち込まない |
| R3 | 言い切らない。対象と、対象が引く原典は本文で読み、引用には頁か場所を添える |
| R4 | 出力は LLM の読みとして書き、pjdhiro の判断として書かない |

適用しないもの：`CLAUDE.md` と、この repo で作業するための決まり（git・セッション・付箋帳・公開前の点検・判断のページ）。

## 7. 適用範囲

| 項目 | 内容 |
|---|---|
| 主な効果 | メタ認知のスキル。発達段階の移行に効く |
| 効きやすい場面 | 自己実現の過程 |
| 副作用 | 理解が進むほど低次の欲求を譲る方向に動き、低次欲求の欠乏を招くことがある |
| 効き方の個人差 | 利用者の認知の水準と性格によって効き方が違う |

## 8. 既知の制約

| ID | 制約 |
|---|---|
| C1 | 論拠は pjdhiro 一人の体験（N=1）。統計的な裏付けではない |
| C2 | 体験に合う論が集まる偏りがある |
| C3 | 一つのチェッカーとして設計している。ほかのチェッカーとの併用を前提とする |
| C4 | 依存モジュールの根が共通のため、複数モジュールの結果は独立した判定にならない |
| C5 | 誤検知の率は測っていない |
| C6 | 要約されると、検出の要になる二面性が落ちやすい |
