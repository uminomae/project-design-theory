### 0.1 考え方

- **評価するのは、このサイトが自分の目的をどこまで果たせているか。** 公的な基準にページがどれだけ当てはまるかではない（pjdhiro「このサイトの目的に照らして、その目的が達成できてる度合いを評価したいんだよ」）。
- **順番**：(1) 目的（README・`docs/DESIGN-INTENT.md`）から始める → (2) 目的ごとに、果たせたかを判定できる基準を探す（公的な基準を先に） → (3) 段 0：その基準で評価できそうか、どれくらいのことが言えそうかを調べる → (4) 評価できそうな基準だけを公開のリストに載せ、ほかは「評価できない」と理由とともに 0.3 に記録する。
- **Claude に任せられないこと**：評価できるかの判断、尺度への当てはめや判定は pjdhiro が見る。Claude が単体で出せるのは、調べた論文の要約くらいまで（pjdhiro「claudeが単体で仕上げられるレベルではない」）。下調べの段階のものを、評価できたかのように公開しない。
- **公開**：評価に関わる公開ページの直しは、pjdhiro が見てから main に出す。
- **進め方**：小さく絞り、一つの小さな成功事例を形にしてから次へ進む。手戻りを避ける。長い調べはトークンが余っているときにする（pjdhiro 2026-11-27「今は、絞って、小さな成功事例を作り、一つずつ形にしていきたい。手戻りしたくない」）。
- これまでのずれ：基準を先に選んでページを当てはめ、評価できたかのように公開した。測れたのは「どの話題に触れているか」で、目的を果たせているかではなかった（stance 2-7・corrections の型 E・H の 2026-11-27 の行）。

## 1. 決め方

- **どの目標も、段 1 の前に段 0「評価できるかを調べる」を置く**。調べるのは、選んだ基準が何を・誰が・どう採点するものか、この repo のページに当てる使い方がその基準で認められているか、当てたら何が言え、何が言えないか。評価できるかの判断は pjdhiro がする。段 0 が済むまで、下の段の条件と結果は案で、公開しない（pjdhiro「まずどう評価するのか？できそうか？という判断がclaudeにはできないでしょう。そのための下調べの段階で、もう評価できるかのように公開している。この判断力では任せられない。評価できそうか？を調べないと。」・2026-11-27）。これまで段 1 として作った表（3.1・3.2）は、段 0 を飛ばしたもの。
- 段 0 で調べるのは、評価できるかと、どれくらいのことが評価できるか。評価できそうな基準だけを公開のリストに載せ、それ以外は「評価できない」という判断を、理由とともにここに記録していく（pjdhiro「できそうな基準だけをリストに公開する。それ以外は、評価できない、という判断を記録していく。だと思うよ。」「どれくらいのことが評価できそうか？も調べないとね。」・同じ日）。

- 目標を二つの枠に分ける。枠 1 は、公的な機関が出した基準・分類で測るもの。枠 2 は、公的な基準が見つからず、確からしい指標を pjdhiro と作るもの。利用する人が気にするのは客観的に評価できるかどうかなので、公的な基準を必ず参考にし、そうでないものは別枠で評価する（pjdhiro 2026-11-26）。
- 測りにくいもの（暗黙知がどれだけ形式化されたか＝判断を写す）は後回しにし、定量化・評価できそうなものを先にする（同じ日）。
- 段ごとの条件は、誰が数えても同じ答えになるもの（件数・率・有無）だけにする。条件がそろったら Claude が記録を添えて知らせ、段を上げるかは pjdhiro がしっくり感で決める。上げたら、リリース文を差し替える。
- リリース文に書くのは、測ったことと、まだ測っていないことだけ。効き目を勧める文にしない（`docs/rules/stance.md` 1-4「優れたものとして推奨しない」・2-6・2-7）。作った指標で測ったものは、作った指標であることをリリース文にも書く。
- 公開するのは、公的な基準で測った二つ（3.1 C の能力の枠組み・3.2 D の学問の区分）だけで、品質を上げていく前提で出す。ほかの目標の結果（B・E・枠 2・A）と、二つのページの直しは、pjdhiro が見てから main に出す（pjdhiro「企画としては良かったが公開するにはクオリティが低いね。公的な基準で測ったものの二つに絞って品質を上げていくことを前提に公開し、それ以外は私のチェックなしには表に出さない方がいい」・2026-11-27）。
- 合格線の数（観点 2 以上・14 のうち 10・20 件）は Claude の案で、決まるまで「案」と書く。
- repo のページへの当てはめは Claude の読み。リリース文に使う前に、別のコンテキストで照合し直す。
