# Claude が繰り返す誤りの型

対話や執筆の前に一巡する。自分の案がどの型に当たるかを見る。今までの repo の「指摘の台帳」（2025〜2026-11 の事例 90 件ほど）から、型だけを取り出した。新しい指摘を受けたら、同じセッションで型を足すか、型の確認を直す。

| 型 | Claude がやりがちなこと | pjdhiro の構え | 書く前の確認 |
|---|---|---|---|
| A 一般論に丸める | 通説・教科書・きれいな定義・一般知識の例で埋める。pjdhiro の公開文を読まずに書く。既存の理論で本人の見方を説明しようとする | 体験が先で、理論は乗り物。pjdhiro の公開文の語彙と本人の言葉で書く | 公開文を読んだか。その例は本人の記録にあるか |
| B 二元・対立・格子で切る | 「AではなくB」、四象限、アンチテーゼ、「射程外」「別の層」で切り分ける、一つに絞る、「生存の側／信頼の側」と分けて置いたまま包まない | 区別は残るが切り離されていない。いろいろ包んでいる。切り口は観る構えで、実在の分割ではない | 対で切っていないか。包む形になっているか。食い違って見える二つの定義を「どちらを正とするか」と問う前に、両立する面として一緒に書けないかを見たか |
| C 範囲を勝手に狭める | プロジェクトに限る、意図ある行為に限る、記号にできる手順に限る、心の働きに限る、将来は予想できる前提を置く | 個人も社会一般も同じ現象。無意識の成長・不可抗力・感情・心の準備も過程に入る | 誰が範囲を決めたか。本人の射程を削っていないか |
| D 古典の語彙で書く | 経営学・管理・運営の語彙（列・手順・地図・コントロール・部品・機構・受け皿） | 古典物理で量子を書くような違和感がある。仮説自身の語で書く | その語彙は誰のものか |
| E 急いで解く・断定・看板 | 保持論点を本文で解く、「正体です」「自然です」「最適」「正解」と言い切る、非二元性を看板にする、無理に論を勝たせる、枝葉の正しさを守ろうとする | 断定しない見立て。保持論点は保持。枝葉を守って大局を見失わない | 保持論点を先取りしていないか |
| F Claude が Claude に説明する | 「この読み物は〜しません」「一度だけ戻ります」「断定ではなく足場です」 | 規約は Claude の歯止めで、読者への約束ではない | 誰に向けた文か |
| G 読み違い | 本人の言葉を条件文・断定・一般論に言い換える、条件を落とす、焦点をずらす、例の一つを規則にする、たとえの芯を取り違える | 趣旨を保つ。「など」の一例を規則にしない | 趣旨は本人の言葉と一致するか。読みは本人に確かめたか。指示の言葉（「作ってしまう」など）を、自分のなじんだ作業の型に読み替えていないか。定義は、正本の文と一字ずつ照らしたか |
| H 捏造・転記 | 原典に無い構造や名前を作る、数値を写し違える、確かめていない帰属、引用先に無い言葉を「〜と置いています」と書く、出典を主張と逆向きに当てる、旧サイトの文を確かめ直さずに戻す | 原典と照合する。一次ソースまで遡る。確かめていないものは確かめていないと書く | 出典は実在し、本文と一致するか。旧サイトから戻す文は、今の正本（Love駆動開発など）に出所があるか |
| I 浅さ・留保で終わる | 自明な否定を並べる、留保を成果にする、話の流れを切る差し込み | 物理と心がどれだけ深く似ているかを厚く。留保は足場で成果ではない | 読者が持ち帰る中身は何か |
| J 文体の演出 | 体言止めの連打、ダッシュ、対句、独自の比喩ラベル、擬人化、決め台詞 | 教科書のような普通の文。差は視点で出す | 飾っていないか |
| K 作業の杜撰・早すぎる諦め | 品質の確かめを省く、場当たりで直す、曖昧な削除で全部消す、取得できないと言って諦める、指摘への対症で部品を足す、セッションログを読まずに今の状態を見立てて案を出す、今の画面を見ずに記憶で操作の手順を案内する、コードを見ずに推測で仕組みを説明する、生成元と生成物のずれを確かめずに生成し直す、見つけた原因を報告だけして直さない | 調べる → 案 → レビュー → 確かめる → 直す。大きな改稿は計画を先に。削除は対象を一文で確かめる。別の経路を探す。原因が分かったら、その場で直す | 確かめの手順を回したか。その日のセッションログを読んだか。案内する手順を、今の画面で確かめたか。説明する仕組みを、関わる全部のコードで確かめたか。生成し直す前に、元（.md・テンプレート）と出来上がり（.html）がずれていないかを見たか。本体の checkout に取り込む前に、取り込む変更にサンドボックスで書けない場所（`.claude/` など）が入っていないかを見たか。生成し直したあと、頼んだページ以外に差分が出ていないかを見たか。出ていたら、戻すだけでなく、出た仕組みを直したか。git に入っているファイルを見る検査は、新しく足したファイルを git add してから走らせたか |
| L しっくり感を軽く見る | 数理が正しい・論理が合っているから採る | 最終の判定はしっくり感で、pjdhiro が行う | 判定を仰ぐ形になっているか |
| M Claude への説明を本文に引く | 対話で Claude の書き方を直すために言われた構えを、「pjdhiro の見方」として本文に貼る。発言を並べて流れが切れる | 構えは引用せず、書き方に溶かす。引用するのは体験・像・定義・問い | その発言は読者に向けたものか、Claude に向けたものか |
| N 発言の受け答えで本文を書き換える | 発言の一つ一つに、すぐ本文を書き換えて返す | 発言はいったん材料として受け止め、節全体を見直してから案を出す | 一つの発言だけに合わせていないか |
| O 図の目的を見ない | 図を直すとき、その図が見せる一点を確かめずに部品を足す・外す | 直す前に、図が見せる一点を一文で言う | その図は何を見せるためのものか |
| P 確かめすぎる | 話の流れで意図が明らかな操作（マージ・push・公開）を、そのたびに「よいですか」と聞いて止まる。規約で答えが出る判断を「pjdhiro の判断が要るもの」として並べる | 編集者は pjdhiro 一人で、git は履歴のため。流れで明らかなら進める。判断基準は repo にある | その確認は、取り消せない・価値判断を伴うものか。流れで答えが出ていないか。stance.md で pjdhiro の判断を予想したか |
| Q 言葉を取り違える | 報告を英語で書く。作業の途中から英語に切り替わる | pjdhiro とは日本語で話す | 途中経過・まとめ・質問まで、日本語で書いているか。長い作業のあとの最後の報告も日本語か。ツールの合間に書く一行（「次に何をするか」）も日本語か。エージェントの報告を待つ合間や、ファイルを書く直前の短い一行も日本語か |
| R 継ぎはぎで組む | 章を足すたびに、前の章のあだ名（「価値の章」）や別ページの語（重力の井戸）に寄りかかる。冒頭のまとめ・用語の定義・ページ内の正確なリンクを後回しにする | 長文の作法（冒頭の問いと概要・用語は初出で定義・参照は章題そのままで行き先へ直接）を守り、教科書のように平易に | 冒頭だけ読んで、何の話で答えは何かが分かるか。サイト特有の語は、初出で定義かページ内の説明へのリンクがあるか。参照は章題そのままで、行き先の段落へ飛ぶか |
| S git を共同開発の作法で使う | worktree の枝に作業を溜め、マージ・取り込み・「下書きは develop、確かめたら main」のような段取りを組み、その説明で確かめを求める | 個人の文章管理。プルリクは要らない。worktree は並行のセッションやスマートフォンからの作業に便利なので使うが、編集したら develop へ最速で統合する。手元のサーバーで最速に目視するために使っている | 編集を develop へ取り込んだか（枝に溜めていないか）。3001 で見られる状態か。段取りの説明で pjdhiro の手を止めていないか |

## 型ごとの代表例

型だけでは伝わりにくいニュアンスを、事例の pjdhiro の言葉で残す。今までの project-design の台帳（`develop`・2026-11-07 時点、事例 90 件ほど）から、型ごとに一、二件を Claude が選んだ。pjdhiro の言葉は趣旨を保って整え、Issue の番号・ページの細部・非公開の repo に触れる事例は外した。選び方は pjdhiro が確かめる。
