# 調べ方と原典の照合

調べもの・原典の取得・照合の規約。今までの repo の規約（原典の取得と照合の規律・出典ノートの不変条件・調査の共通指示）と、pjdhiro の指摘と判断から、趣旨を取り出してまとめ直した。見方と判断の仕方は `stance.md`、書き方は `writing.md`。

## 1. 何のために調べるか

1. Claude に期待されているのは、pjdhiro の問いや仮説に対する正確な調査。創造性の披露ではない。（2026-07-04）
2. 新しい視点・主張・脇道は歓迎される。ただし、調べて確かめた事実と区別できる形で出す。
3. 研究は大いに参考にするが、それを論拠に演繹しない。どの研究も一面。前提の知識も「そう言われてきた」もの。実証の厚み（経験則・実証済み・見送り・仮説）は項目ごとに正直に書く。（2026-07-04・11-04）
4. 物理や数学では、pjdhiro は真理を追っていない。持っていない視点を得るために使っている。真偽を pjdhiro が判定できないので、確かさの仕分けは Claude が引き受ける（§6）。（2026-11-05）
5. 「〜を直接示した研究には当たらなかった」と書けることも成果。無理に論を勝たせない。

## 2. 文献から調べる

1. 訓練で覚えた知識を合成して書かない。文献から調べる。（2026-04-16「それらを文献からリサーチする必要があるのですよ」）
2. 言葉一つ一つの定義を大切にする。似た概念を一緒にしない。たとえば、間主観性は本能のようなもので、情動伝染はそこに影響を与えるだけ。（2026-04-16）
3. 原典に無い構造・名前・体系を作らない。LLM が作った体系（「5 つの柱」「4 層モデル」「定義番号」など）は、原典に根拠が無ければ削る。（2026-04）
4. 兄弟の論（創造とは・欠損駆動思考・意識とは）に、すでに調べた跡がないかを先に見る。読まずに「未確認」と言わない。（2026-11-06）
5. 一次情報は、URL があるか、ダウンロードできるものを探す。pjdhiro も見ることができ、第三者がチェックできるもの。それを分野ごとに淡々と進める。判断基準が明確なら、時間さえあれば自律的に進められる。記録には、確かめ先（URL・DOI）と読んだ頁を残す。開けない文献（紙の本だけ・有料の壁）は、照合の状態を正直に書き（§3）、開ける一次情報を別の経路で探す（§5）。（2026-11-08・cs のレビューの計画で）
6. すでに集めた原典（台帳・手元の PDF・精読ノート）をベースにし、不足している分野はさらに探す。（2026-11-08・cs のレビューの手順で）

## 3. 照合の状態を書き分ける

出典ごとに、どこまで確かめたかを書く。

| 状態 | 意味 |
|---|---|
| 本文照合済 | 原典の本文を読み、該当箇所をページつきで確かめた |
| 要旨照合済 | 要旨（abstract）まで確かめた。本文は読んでいない |
| 二次資料のみ | レビュー・解説・事典などで読んだ。何の二次かを書く |
| 未照合（理由） | 本文も要旨も読めていない。括弧の中に、読めなかった理由を下の 7 の語で書く。「未照合（記憶）」は、記憶で書いて書誌も内容も確かめていないもの |

1. 確かめていないものは、確かめていないと書く。推測で書誌（巻号・ページ・DOI）を埋めない。
2. 二次資料の中の引用は、原典のページを確かめるまで「二次経由」と書く。
3. 公開文に載せるのは、原典の本文を読んで確かめたものだけ。書誌だけ・要旨だけ・二次資料だけ・記憶だけのものは載せない。取れなかった文献の一覧や「まだ読めていない」という断り書きも、読み物には置かない（原典の台帳の扱いは stance 2-7 の行）。読めなかった出典は、照合の状態ごと手元の記録（Issue・evidence）に残し、本文が読めたら載せる。（pjdhiro 2026-11-09・#79 の「Love とは、どう言われてきたか」で、書誌のみ・要旨照合済の行を見て「一次情報が取れないなら掲載してはダメなんじゃ」「本文を読めたものだけ」、取れなかった PDF の一覧について「これは載せないほうがいい」。2026-11-07 の「未照合と書いて載せる」を改めた）
   - 古いものは、翻訳者などの解説でも構わない。（pjdhiro 2026-11-09・#79 のまとめの章で、本文を読めておらず表に無い区別があることを見て「出典が確認できないものはなるべくあげたくないが、古いものは翻訳者などの解説でも構わない。」。どこからを古いものとするかは、聞いていない。使うときは、その解説を開いて読み、訳者・書名・位置を書き、原典の文でなく訳者の解説と分かるように書く。この一文は Claude の運用）
4. 「〜と書いています」「〜と置いています」と書く前に、引用先にその言葉があるかを突き合わせる。言い換えが引用先の定義を変えていないかを見る。（2026-11-05）
5. 出典は、主張と同じ向きに当てる。主張と逆のことを言う研究を裏付けに使わない。（2026-11-05）
6. 帰属を確かめる。pjdhiro が話すことには、本人の見方と、本人が読んだ他の人の論とが混ざる。他の人の論は、その人の問いごと帰属する。（2026-11-06「それは新田の論です」）
7. 「未照合」の括弧の中に書く、読めなかった理由の語は、次の七つにそろえる。調査の記録（cs・as の evidence）で数えると言い方が 116 通りあり、同じことを違う語で書いていた（2026-11-10・Issue #111 のレビュー）。語は、今ある記録でいちばん多い形を採った。新しい語を作らない。記録と as の台帳は、2026-11-11 にこの語へそろえた（130 か所）。括弧の頭がこの語かは、`scripts/check-cs-evidence.mjs`・`scripts/check-as-evidence.mjs` が見る。

   | 語 | いつ使うか | 記録にある、同じ意味の言い方（この語にそろえる） |
   |---|---|---|
   | 未照合（記憶） | 記憶で書いた。書誌も内容も確かめていない | 記憶。書誌も内容も確かめていない |
   | 未照合（書誌だけ） | 書誌（著者・年・題・DOI）は確かめた。本文も要旨も読めていない | 書誌のみ・書誌だけ確かめた・書誌のみ Crossref |
   | 未照合（書籍） | 原典が本（本の章を含む）で、無料で読める版が見つからなかった | 書籍を開けなかった・書籍・章とも開けていない |
   | 未照合（有料） | 論文が有料の壁の向こうで、無料で読める別の経路（§5 の決まり 2）も見つからなかった | 有料で、要旨も読めていません |
   | 未照合（確認画面） | 取りに行った先が確認画面や 403 を返し、ブラウザでの保存（§5 の決まり 6）がまだ | 自動取得が確認画面・ブラウザでの保存が要る |
   | 未照合（上げた人の分からない写しで読んだ） | 本文を開いたが、載せてよい写し（§5 の決まり 8）でなかった。読んだ頁は書く | 個人が上げた写しで読んだ・権利の確かめられない写しで・第三者が置いた写しで・利用者が上げた写しで・上げた人を確かめていない写しで本文を読んだ・Monoskop の写しで読んだ |
   | 未照合（原典が特定できない） | 論の出どころとして読むべき原典が、一つに決まらない（報告が原典を挙げていない など） | （記録に 2 か所。この語のまま。2026-11-11 に足した） |

   括弧の中に書いてよいこと：
   - 頭に、上の語を一つ。一つの論に文献が二つ以上あって理由が違うときは「と」でつなぐ（「書籍と有料」）か、文献ごとに書く。文献ごとに書くときだけ、どの文献かを示す年を語の前に置いてよい（「本文照合済（2000 の著者稿）・未照合（2003 の書籍）」）。
   - 語のあとに句点を置いて、短い補い（どの文献・どの版・どの写し・どのホストか・読んだ頁）を足してよい（「書籍。Internet Archive の貸し出し」「有料。ACS・AIP とも 403」「上げた人の分からない写しで読んだ。pp.118・120」「有料と書籍。書籍は Jenny 1941」）。上の年のほかは、語の前に何も置かない。
   - ほかの記録を指すこと（「社会学の記録を参照」）と、いつ状態を改めたかの経緯（「2026-11-09 の一巡で、本文照合済から改めた」）は、括弧に入れず、括弧のあとの文で書く。
   - 要旨は読めた・二次資料で読んだものは「未照合」でなく、表の「要旨照合済」「二次資料のみ」。

- 載せてよい写しの範囲は、§5 の決まり 8 に一つにまとめた（2026-11-10。ここにあった「写しの置き場で分ける」の行もそこへ移した）。

## 4. 読む

1. 条件や結論を書く前に、その節を頭から読む。最後のページの一例を、論文の主張の全体として書かない。（2026-11-07）
2. 原典は、全文か主要部を読んでから書く。要旨だけで本文の内容を書かない。
3. 鍵になる文は、原文のまま短く（一か所 40 語ほどまで）、ページ番号をつけて控える。訳は添えてよいが、訳で原文を置き換えない。長い引用や全文の転記はしない。
4. 原典の言葉を中立な定義として写す前に、その言葉がどんな人の像で書かれているかを見る（`writing.md` §7）。
5. 同じ理論が別の調べ（分野・領域・読み物）にも出るときは、先に済んだ記録で本文照合済の所を読み直さず、その記録を参照して書く。重なっていることは一行で書く。（2026-11-08・創造とはの心理学の分野で、予測処理が神経科学と重なった。意識とはのレビューでも同じ。2026-11-10 に `docs/cs-review/README.md` から上げた）
6. 手元の PDF が画像だけで、文字に起こすと空のときは、同じ資料の OCR の文字（Internet Archive の `_djvu.txt` など）か、頁の画像で読む。照合の状態に「OCR の文字で読んだ」「頁の画像で読んだ」と添え、台帳の行にも書く。（2026-11-08・創造とはの経済学の分野のケインズ 1936・シュンペーター 1939。2026-11-10 に同じ文書から上げた）
7. 公開の PDF は、ページを取ってきて要約させる道具（WebFetch）では本文を読めないことがある。保存した PDF を pdftotext で文字にして、鍵の文を grep で引いて読む。（2026-11-10・Issue #111 で、物理に触れる読み物の出典をこの手順で読んだセッションの報告から）

## 5. 取得する

原典の置き場所は、決まった順番で探す。経路を思いつきで選ぶと、早く当たったところで止まったり、同じ名前の別の文献を掴んだりする（2026-11-09・stages-screener の出典の行が、Starr & Torbert 2005 の名前のまま別の論文の PDF を指していた。Cook-Greuter 2013 は個人の写ししか無いと思っていたが、著者の昔のサイトにあった。pjdhiro「claude は間違えたり、見つけられなかったりする。どうすれば精度が上がるか」）。

### 順番

道具は `scripts/find-source.sh`。使い方・結果の読み方・写しの性格の書き方・止めどころは、スキル `find-source`（`.claude/skills/find-source/SKILL.md`）にまとめてある。ここには順番と決まりだけを書く。

1. **スクリプトで全部引く**：`bash scripts/find-source.sh find` に DOI か書誌の一行（`--cite`）か題（＋著者・年）を渡す。Crossref（書誌の確定）→ Unpaywall → OpenAlex → Semantic Scholar → Europe PMC → CORE → Internet Archive（本・DOI の無い文献・古い文献）→ Wayback（`--url` で渡した URL そのものの写しと、`--domain` で渡した著者のサイト・雑誌のサイトの PDF の一覧）を、早く当たっても止めずに全部引く。見つかった場所は、取りやすい順に、「誰が上げた版か」（出版社／大学・機関リポジトリ／著者のサイト／授業・個人の頁／個人／不明）と「自動で取れそうか」つきの表で出て、頭に判定が一行で書かれる。
   - 著者のサイトと雑誌のサイトは、今のものと昔のもの（Wayback）の両方を `--domain <ドメイン>:author`・`:publisher` で渡す。確認画面で止まった PDF の URL は `--url` で渡す（同じ URL の Wayback の写しを引く）。
   - 連絡先のメール（Unpaywall に要る）とキー（CORE ほか）は、環境変数で渡す。repo には書かない。無ければその経路は「飛ばした」と表に出る。
   - Crossref が「近い候補なし」「著者が違う」と言ったら、その DOI を使わない。DOI の無い文献（未刊の論文・小さな雑誌・本）のことが多い。年の食い違い・題の重なりの少なさの注意が出たら、巻と頁を目で確かめる。
   - 「誰が上げた版か」「自動で取れそうか」はドメインと API の返事からの見立て。載せる前に、その頁を開いて上げた人を確かめる（下の 8）。
   - 表に無い経路（著者の出版物の一覧・大学の図書館・講演・訳の公開アーカイブなど）は、そのあとに試す（下の 1）。
2. **取って、突き合わせる**：判定が「自動で取れそう」なら `bash scripts/find-source.sh fetch <場所> --out <保存名> --cite …` で一度だけ取る。道具は、先頭が `%PDF` か、途中で切れていないか、頭の頁の題・著者・頁数が合うかを確かめてから保存し、確認画面・ログイン・403 を返したホストを手元の一覧に足して止まる（下の 2・3・4・7）。手元にある PDF は `check <PDF> --cite …` で同じ突き合わせをする（頁の範囲・掲載誌・再録や訳の印・本の前付けだけ、も見る）。写しを差し替えるときは `compare <前の写し> <新しい写し>` で、本文の語の並びを突き合わせる。
3. **台帳に残す**：`find`・`batch`・`discover` に `--ledger <ファイル>` を付けて、試した経路と結果を追記する。次のセッションが同じ場所を叩かないため（下の 2）。創造とはの分野のレビューでは `cs/knowledge/raw/find-ledger.md`、それ以外は `.cache/raw/find-ledger.md`。どちらも git の外なので、worktree で作業するときも本体の checkout の側に書く（場所は `git rev-parse --git-common-dir` の一つ上。worktree の中に書くと worktree と一緒に消える）。探す前に台帳を開き、すでに試した経路を先に見る。台帳の行や表をまとめて引き直すときは `batch`（済んだものは飛ばす）。
4. **最後に pjdhiro に手で開いてもらう**：自動で取れなかったもの（確認画面・ログイン・403・貸出だけ）だけを、一件ずつ表にして頼む（下の 7）。列は、開く URL・ページ内で探す語・持ち帰るもの（貼る範囲、または保存先と保存名）・それで何を確かめるのか。何を見ればよいかが分からない頼み方をしない（corrections 型 R）。

### 広く探す

なるべく広く論文を探すのは良いこと（pjdhiro 2026-11-09）。置き場所を引く `find` とは別に、主題や理論の名前・ある論文を引用している論文・その参考文献・著者の論文を、OA かどうかつきで並べる入口 `bash scripts/find-source.sh discover` がある。出るのは候補の一覧で、被引用の数は論の確かさではない。選んだものを `find` → `fetch` → `check` → 読む、の順に進め、読めたものだけを使う（§3）。見つけたものを分野の論として足すかは、その作業の目安に従う（創造とはのレビューでは `docs/cs-review/README.md`「調査の手順」）。

### 決まり

1. 早く諦めない。取れないと言う前に、別の経路を四つ以上試す（オープンアクセスの検索・著者や大学のサイト・機関リポジトリ・学術検索の PDF リンク・公開書籍のアーカイブ・書籍の検索 など）。（2026-06-26 の指摘）
   - 本が読めないときは、その著者が足場にした原典を探す。学者の主張は、誰かの主張を足場に書かれている。足場は、読める書評・紹介文・その本を引く論文から拾う。（pjdhiro 2026-11-10・#108 で、國分功一郎『中動態の世界』もバンヴェニストの訳書も持っていないと答えたあとに「日本人の学者の主張は誰かの主張を足場に記述するはずなので原典を探せば見つかると思う。」。探した結果、足場のうち古いもの〔トラクス・スピノザ〕は無料で読め、芯の Benveniste 1950 は著作権が切れておらず読めなかった。足場が新しく、著作権の切れていない原典のときは、この経路でも読めないことがある）
2. 同じ方法で同じ場所を何度も叩かない。自動取得を拒むサイトや、出版社の 403 は、繰り返しても取れない。そのときは pjdhiro にブラウザでの保存を頼む。頼むのは、無料で読めるのに自動取得だけが拒まれるもの。有料の壁で止まるものは頼まず、決まり 6 の下の行のとおり、無料で読める別の経路を探す（2026-11-10 の「有料のものは参考にしない」があとの決め。二つの関係を書いたのは Claude で、pjdhiro に確かめた）。保存を頼んだものも、ダウンロードして読むまでは論拠にしない。（pjdhiro 2026-11-10・Issue #111 の判断のページへのコメント。この関係でよいかを聞いたときに「それでいいけど、ダウンロードして読むまでは論拠にしないでね。それだけ注意事項。」）
3. 取れたかどうかは、返事の番号でなく中身で判断する。PDF なら先頭が `%PDF` か。HTML の案内ページを掴んでいないか。
4. 取れたら、書誌を突き合わせる。著者・年・題・DOI が狙った文献と一致するか。同じ名前の別の論文を掴むことは何度も起きている。違えば捨てて記録する。
5. 書誌は二つ以上の独立した情報源で確かめる。食い違いは両方書く。
6. 図書館の相互貸借・本の購入・著者への連絡など、お金や手続きが要る手段は、Claude は候補と費用感を出すところまで。決めるのは pjdhiro。
   - 有料のもの（出版社の有料の論文・購入や相互貸借でしか読めないもの）は参考にしない。別の経路で、無料で読めるもの（著者・大学の写し、同じ著者の OA の論文や総説など）を探す。見つからなければ使わない。（pjdhiro 2026-11-10・ks の調査 #98 で、有料の原典 5 件を相互貸借や購入で取るかを聞いたときに「有料のものは参考にしない。別の方法で探す。無料のものを。」）
7. 自動取得が確認画面やログイン画面で止まる PDF は、別の名乗りで取りに行かない。Issue に、文献・ダウンロード先・保存先と保存名の案を表で残し、pjdhiro があとでまとめてブラウザで保存する。（2026-11-08・cs のレビューで「issue にダウンロード先を残していって。あとでまとめてやる」）
8. 載せてよい写しの範囲は、ここで定める（`review.md` の機械の点検もここを指す）。本文照合済として載せてよい：出版社の公開版・パブリックドメイン・CC／著者本人や関係者・大学（研究室・機関リポジトリ）・公的機関・信頼できる企業のサービスに置かれた写し／Wayback に残っていた出版社の PDF。載せない：個人が上げた、権利を確かめていない写しだけで読んだもの。どれも、誰が上げた写しかを確かめ先に添える。それぞれの決めと経緯は下の行（2026-11-10・三か所で範囲が違って読めたので、頭にまとめた）。個人が上げた写し（archive.org など）は、読んでよいが、確かめ先には「個人が上げた写し。権利は未確認」と性格を添え、それだけで本文照合済としない。パブリックドメイン・CC・出版社の公開版があればそちらを書く。翻訳で読んだときは、訳者・版・ライセンスを書き、状態に「（訳）」を添える。（2026-11-08・cs のレビューの D14・D18 で）
   - 著者本人か大学（研究室・機関リポジトリ）が上げた写しで本文を読んだものは、本文を読めたものとして載せてよい（§3-3）。確かめ先に、誰が上げた写しかを添える。個人が上げた権利未確認の写しだけで読んだものは載せない。（pjdhiro 2026-11-09・#79 で、出版社の版でない写しの扱いを聞いたときに「著者・大学の写しは載せる」）
   - 写しの置き場で分ける：著者本人や関係者、公的機関、信頼できる企業のサービスなどに置かれた写しは、匿名の個人が上げた写しとは違う。少なくとも著作権に配慮されているものは、本文照合済として採る方向でよい。置き場の性格は添える。（2026-11-09・cs のレビューの判断待ちのページへのコメント・伝統知の記録の Berkes ら 2000 が、カナダの資源の共同管理の機関のサイトの写しだったときに）
   - Wayback（Internet Archive）に残っていた出版社の PDF は、性格を添えて確かめ先にしてよい。確かめ先には「Wayback の記録（元は出版社の …）」と写しの日を書く。（pjdhiro 2026-11-09・#73 で、確認画面で止まった PDF の URL そのものの写しが Wayback に残っていて 19 本取れ、元が有料の誌面かもしれないもの（Nature 1966 など）が混ざると伝えて「Wayback に残っていた出版社の PDF を、性格を添えて確かめ先にしてよいですか？」と聞いたときに「よい」。公開ページに出す確かめ先は DOI を先に書く、は Claude の運用）
   - 個人の写ししか見つからないときは、外す前に、著者のサイト（今と昔。Wayback の一覧 `web.archive.org/cdx/search/cdx?url=<著者のドメイン>*` で PDF を探す）・著者の出版物の一覧（ResearchGate など）に同じ文書がないかを探す。見つかったら全文を突き合わせ、一致すれば確かめ先をそちらに差し替える。（2026-11-09・Cook-Greuter 2013 は、pjdhiro「なんとしても探して欲しい」で探し、著者が cook-greuter.com に置いていた版が個人の写しと一字も違わないことを確かめた）

## 6. 物理の主張の三つの区別

物理や数学を構造の類似に持ち込むとき、Claude の主張に三つのどれかを添える。

| 区別 | 意味 | 扱い |
|---|---|---|
| 教科書 | 分野で確立した記述 | そのまま足場にしてよい |
| 研究の一線 | 争いがある、または一つの研究が示した | 「〜という立場がある」と書く |
| Claude の読み替え | pjdhiro の問いに当てた Claude の解釈 | 見立て。採否は pjdhiro のしっくり感 |

確かめるときは、合うところを増やすより、その構造が禁じるものを探す。

## 7. 数字を伝える

1. 数・人数・年・比率は、公開文から一次の調査ノートや原典まで直接たどって確かめる。途中のレビュー表の「照合済み」を信じない。（2026-07-16 の転記ミスから）
2. 誤りを見つけたら、公開文だけでなく、誤りの出どころの記録も直す。

## 8. 原典ファイルの置き場所

1. 原典のファイル（論文の PDF・本のスキャン）は、この repo に入れない。この repo は公開で、著作権のある原典を配ることになる。
2. 原典は手元の `.cache/raw/` に置く（`.gitignore` 済み）。創造とはの原典は `cs/knowledge/raw/` に置く（`.gitignore` 済み。台帳の `manifest.md` だけ公開）。意識とはの原典は `as/knowledge/raw/` に置く（`.gitignore` 済み）。確認画面を返したホストの一覧（`find-hosts.tsv`）と、試した経路の台帳（`find-ledger.md`）の置き場は、スキル `find-source` の「台帳」「取る」に書いてある。repo に書くのは、書誌・取得先・照合の状態・鍵の文だけ。台帳の状態の列は、記録に合わせて上げる：記録が本文を読めた原典は、台帳の状態も上げる。論拠にするものは、読めたものだけ（§3-3）。（pjdhiro 2026-11-10・Issue #111 の判断のページへのコメント。創造とはの原典の台帳の状態が記録より古いので、記録に合わせて上げるかを聞いたときに「やって。」「論拠にするも音は読めたものだけ」。「も音」は「もの」の誤字と読んだ）

## 9. 今までの調査結果を使うとき

今までの repo の調査結果（knowledge・evidence・調査メモ・wiki）は、以前の LLM と作ったもので、そのままは使わない（`docs/BUILD-PLAN.md`）。

1. 要る主張だけを取り出す。
2. この文書の §3〜§5 で、一次ソースと照合し直す。
3. 通ったものを書き直す。何をどの一次ソースで確かめたかを添える。
4. 今までの調査結果にあった書誌は、探す手がかりとして使ってよい。その書誌自体も確かめ直す。

## 10. 公開ページの出典には原典へのリンクを張る

1. 公開ページに書く出典は、一件ごとに原典へのリンクを張る。マナーとして義務にする。LLM の取り違えや作り話（著者・年・頁・言い回し）を、pjdhiro と読者が原典を開いて確かめられるようにするため。（pjdhiro 2026-11-11・Love駆動開発の「参照の一覧」にリンクの無い出典があったときに「参照にリンクが貼ってないものがある。LLMのハルシネーションなどをレビューするために原典チェックは必須なんだ。ここに限らず、原典への参照リンクはマナーとして義務にして。」）
2. 張り方：DOI があれば著者と年に DOI（`https://doi.org/…`）を張る。読んだ写しが別の場所（PMC・機関リポジトリ・著者のサイト・Internet Archive・Wayback・arXiv）なら、括弧の中の写しの説明にもその URL を張る。DOI の無いもの（本・古い誌面・事典・公的資料）は、読んだ写しかその頁に張る。大蔵経は SAT か CBETA の該当の頁、事典はコトバンクの項に張る。
3. 張る URL は、書く前に確かめる。DOI は Crossref で著者・年・題・巻・頁が出典と合うか、URL は開けるか（Wayback は CDX で記録があるか）を見る。推測で URL や DOI を組み立てない（§3-1）。照合の記録（BIB-check・調査のノート）に URL があればそれを使い、無ければ記録にも足す。
4. 原典が公開されていない（売り物の報告書・会員だけの資料）か、前に読めた頁が消えて今は開けないときは、リンクを張らずに残し、その出典を本文照合済のまま使い続けるかを pjdhiro に確かめる。「公開されていない」と言う前に、調べのノート（`SURVEY-*`・`BIB-check`）の確かめ先の列を開く。公的機関に置かれた写しは、表紙に「引用しないで」の断りがあっても、リンクで残す。（pjdhiro 2026-11-12・心理的安全性の LeaderFactor 2021 技術報告書を、Claude が非公開と取り違えて外すかを聞いたあと、調べのノートにあった reginfo.gov の写しを伝えて「リンクで残す」）
5. 読み物の正本の「出典：」の行は `node scripts/check-source-links.mjs` が見る（`scripts/check.sh` から、リンクの無い出典が一件でもあれば止める）。四つの入口・cs/as/ks の記録の窓など、「出典：」の行の形でない公開ページは、まだ機械で見ていない（`docs/TESTING.md`）。
