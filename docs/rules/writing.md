# 公開文の書き方

公開ページの文章を書く・直すときの規約。今までの repo にあった執筆の規約（project-design の `writing-stage.md`・執筆ルール 1〜25・指摘の台帳）から、pjdhiro の指摘の趣旨を取り出してまとめ直した。特定のページだけに向けた規約は外した。見方そのもの（pjdhiro の言葉と出所）は `stance.md`。ここには書くときの形だけを置く（#74）。

## 1. 声と帰属

1. 公開ページの文責は Claude にある。地の文で一人称「私」を使わない。
2. pjdhiro の言葉は引用として出す。体験・問い・見方・例・たとえ・感想・判定のように、何の言葉かが分かる形にする。引用の前後の地の文で、同じことを言い換えない。
3. 引用で大切なのは趣旨。誤字・脱字は直してよい。条件を落とす・断定に変える・弱めるなど、趣旨が変わる言い換えはしない。
4. pjdhiro の発言に出典や時期を付けない。対話で協働しているので、発言することが本人の関わり方そのもの。日付そのものが中身の年表などは別。
5. 体感のたとえは、たとえとして出す。定義の看板を付けない。
6. 対話の中で、Claude の書き方を直すために言われた構えや訂正は、本文に引用しない。書き方に溶かす。引用するのは体験・像・定義・問い。問いは説明の前に置き、本文がそれに答える形にする。
7. pjdhiro が話すことには、本人の見方と、本人が読んだ他の人の論とが混ざる。引用の前に、誰の論かを確かめる。
8. pjdhiro が原典を読んでいない理論を扱うページは、文責が Claude であることと、本人の言葉は Claude の要約への感想であることを、冒頭に書く。何を読んでいて何を読んでいないかは、本人の言葉どおりに書く。これは pjdhiro が原典を読んでいない場合の話。Claude が本文を読めていない出典は、そもそも載せない（`sources.md` §3-3）。冒頭に置くのは、文責と本人の言葉の性格を言う一、二文だけ。何を載せ、どう確かめたかの説明は巻末に置く（型 F・`decisions.md` の #79 の行）。文責の一文は、確かめ方の説明ではなく、誰が書いたかを読者に先に知らせる一文なので、冒頭に残す。調査の記録の点検（`scripts/check-cs-evidence.mjs`・`check-as-evidence.mjs`）も冒頭の文責を見ている。（2026-11-10・レビューで三つの決めの関係が読めないと指されて関係を書き、2026-11-11 に置き場を決めた。型 F の「巻末に」は確かめ方の説明への指示〔2026-11-09「claudeの言い訳めいたやつ」〕で、文責の一文への指示ではない、と Claude が規約から読んで決めた。pjdhiro が直に答えたものではない）
9. Claude が Claude に説明しない（型 F）。「この読み物は〜しません」「断定ではなく足場です」のような、規約への言い訳を本文に書かない。

## 2. 主張の水準

括弧の番号は `stance.md` の節。

1. 断定しない。中心の主張も見立てにとどめる（2-1）。
2. 保持論点（まだ解けていない問い・不快・混乱）を、本文で急いで解かない（2-2）。
3. 独自の主張を、通説や教科書の説明に丸めない（型 A）。
4. 前提の知識も「そう言われてきた」ものとして扱い、対立の構図で書かない（1-1・1-2）。
5. 調べて確かめた事実と、新しい視点・候補とを、読んで区別できる形で書く。確かめていないものを、確かめたものの中に混ぜない。
6. 網羅しようとしない（2-6）。読み物は要所をつなぐ事例の報告で、論証ではない。飛躍を説明で埋めず、ほかの可能性は「ほかにもあるはず」と短く一回だけ書く。直すのは、本人のやり方と違う記述と、誰の見方か読めない帰属だけ。
7. 売り込み・格上げ・取り繕い・防御の文を書かない（2-6）。
8. たとえと厳密さの両立が難しい題材は、仮の説明として書く。厳密に言うとこう、たとえるとこう、の二つを並べ、あとで直すことがあると書く（1-1）。
9. 東洋の像を紹介するときは、原典の文脈で照合し、文脈と違う読みで引かない。文章のスタンスは 1-4。
10. 群盲象と指月の使い分けは、`stance-theories.md` の指月の行のとおり。

## 3. 見方の構え（発達段階 6.5）

文章とコンテンツの発達段階は 6.5 に置く。pjdhiro に合わせる。

1. 層（体・感情・考え・気づいている意識、または物質・生命・心）を名指しして、互いに入り込み合うように書く。
2. 気づいている意識を、外から眺める位置に置かず、層の一つとして中に入れる。
3. 区別は消さない。「一つになる」「統合される」「超える」と書かない。
4. 非二元性を看板にしない。語でなく、見え方の構造に出す。
5. 複雑さで高く見せない。具体と形而上が一つの文にあってよい。
6. 「〜な瞬間がある」と状態の瞬間として書かず、いつも使える構えとして書く。
7. 読者の段階に合わせて本文の段階を下げない。誤解は先回りの FAQ で扱う。

### 二元論にしない・範囲を狭めない・語彙

見方は `stance.md` の 1-2・1-3・§4 と `stance-theories.md` の創造の行。型は B・C・D。

1. 「AではなくB」で切らない。区別を書くときは「二つに分けて書くが、二つでない」「Aは Bの一つの現れ」の形にする。
2. 「入る・入らない」と線を引く前に、その線に自分の善悪の判断が入っていないかを見る。
3. 「開発」「手順」「創造」の範囲を狭めない（1-3・型 C）。
4. 個人・集まり・社会一般は、同じ現象の規模の違いとして書く。例の場面（プロジェクトなど）と、主張の範囲とを混同しない。
5. 構想・計画・実行の並びは、人が意識して関われる部分を取り出して書いたもので、その並びの外でも過程は進む（1-3）。この並びを「地図」とたとえない（§4 の退ける語。2026-11-10・#108 で、Claude が #86 で書いた「地図のようなもの」を直した）。
6. 「手前」「下」は時間の前後でなく、同時に走っている層として書く。
7. 管理・運営の語彙に安易に訳さない。仮説自身の語で書く（§4 の表・型 D）。
8. 定義の作法（類と種差など）で、記号で表せないものを定義しようとしない。

## 4. 文体

本文は、教科書・ニュース解説のような、無難で普通の説明文で書く。差は文体でなく視点で出す。中学生にも読める平易さを目安にする。

1. 一文に一つのこと。条件・理由・帰結を一文に積まない。
2. ふつうの言葉で書く。理論の語を重ねない。言い換えの説明（「つまり〜」）は一つまで。
3. ヘッジは一文に一つ。いくつかの手がかりは一文にまとめて、ヘッジを一回にする。
4. 言い直しをしない。例や引用のあとで、同じことを言い直さない。
5. 例は「たとえば」で置き、誰の例かを短く添える。「そして」「だから」で論理の帰結のように繋がない。
6. 出典の行は要るときだけ付ける。
7. 演出をしない。体言止めの連打、ダッシュでの余韻、対句、独自の比喩ラベル、擬人化、決め台詞、「〜を思い浮かべてください」のような呼びかけ、溜め、読者への合いの手を使わない。定義や結論を先に普通に述べ、理由や比喩はあとに続ける。
8. 説明の道具としての比喩は使ってよい。飾りにしない。

検証：足した文を前後の文と並べて読み、文の長さとヘッジの数が揃っているかを見る。

## 5. 構成

1. 冒頭に短いまとめを置く。背景（なぜ考えたか）・問い・今のところの答えが、それぞれ一、二文で分かるようにする。
2. 表に出すのは、まとめ・中心の主張・大事な説明だけ。論拠・反論・検証・出典などは畳み（`<details>`）に入れる。畳みの見出しは中身を平易に要約する。
3. 三つの段に分ける。本文（畳みを開かなくても一本道で読める本筋）、「詳しく」の畳み（本筋の同じ話の深掘り）、コラムの畳み（本筋から離れた寄り道）。無関係なことを本筋と同じ段に並べない。
4. 章の頭に、その章が何を見るのかを短く書く。どこから読んでも、中心の問いとのつながりが分かるようにする。
5. 調べた順に並べない。読む人が一本道でたどれる順にする。大きく組み直すときは、先に Issue に計画を書く。
6. 調べた結果は、最新の結論を分かりやすい位置に置く。古い結果は、訂正の筋が追える程度にして畳む。
7. 誤解されやすい言い回しには、誤解の前に補足を置く。誤解を扱うときは、その誤解が生まれる実在の現象を示してから訂正する。補足は本筋への肉付けで、重箱の隅の訂正にしない。
8. 読み物は追体験として組む。pjdhiro が考えた筋・背景・問い・対話で知ったことが順にはっきりしていくように並べる。共感・驚き・納得が運べたらよい。
9. 要約や解説をレビューするときは、5W1H（誰が・何を・いつ・どこで・なぜ・どのように）が盛り込まれているかを確かめる。馴染まない場合は除く。冒頭のまとめにも当てる。（pjdhiro 2026-11-08・Love駆動開発の冒頭のまとめを見直すときに）
10. Love駆動開発の読み物は、pjdhiro の発言に Claude が答える対話の形で進める（`stance.md` 2-4）。一続きを次の五つで組む。
    - 文脈：なぜその発言が出たのかが分かる一、二文。多くは、その発言が答えた問い（対話の中で Claude が聞いた問い など）で、前の章の流れから出てくる形にする。本文の地の文か、問いの小見出しで置く。発言の中身を先に言い換えない（1-2）。対話の記録に問いが残っていれば、その趣旨で書く。残っていなければ、記録にあった問いのように書かず、このページが立てる問いとして書く（`stance.md` 2-4・2026-11-10）。
    - 発言：pjdhiro の問い、または意見。引用カード（`<strong>pjdhiro の問い：</strong>`・`<strong>pjdhiro の見方：</strong>` などで始まる段落。`pd/docs/DESIGN-RULES.md` §13）で出す。見出しは問い・見方の二つに無理にそろえず、体験・たとえ・例など、流れに沿うものにする（`stance.md` 2-4・2026-11-10）。章の起点の発言は、その章が説明することについて言った言葉にする。別の話題で言った言葉を当てはめたとき（当てこみ）は、公開する前に pjdhiro に見せる（2026-11-10・防衛機制の章に、心理的安全性まわりの言葉を当てて「この引用は適切ではないね」）。
    - 答え：問いには、調べて答えた要約。意見には、その解説。本文の地の文で、数文に収める。発言を言い換えず、答えから書き始める（1-2）。
    - 詳細：答えの論拠・数値・原典の照合・ほかの見方。「詳しく」の畳み。
    - 周辺知識：答えの外にある背景や、隣の分野の話。「寄り道」の畳みか、別ページ（兄弟の探究・独立した読み物）へのリンク。

    本文（文脈と発言と答え）だけを続けて読み、一気に読み切れるか、発言が唐突に出ていないかを確かめる。詳細や周辺知識が本文に残っていたら、畳みか別ページへ移す。引くのは読者に向けた問いと見方だけで、Claude の書き方を直すために言われた構えは引かない（1-6・型 M）。答えに要る問いや意見を pjdhiro が言っていないときは、発言を作らずに pjdhiro に聞く（型 H）。手元の `dialogues/` の発言は写さない。

## 6. 読者と AI

1. 公開ページは、人が読めることに加えて、AI が一通りに読み取れることを目標にする。用語は初出で定義して表記を揺らさない。誰の言葉か・確かめた度合いが、本文だけから分かるようにする。ページの外を見ないと意味が取れない箇所を作らない。
2. 大きな更新のときは、文脈を持たない AI にページだけを読ませて解説させ、誤読や二通りに読める箇所を集めて直す。
3. repo 名を本文に書かない。読者に見えるタイトル（プロジェクトデザイン論・創造とは・欠損駆動思考・意識とは）で書く。
4. リンクは公開ページへ張る。GitHub のファイルは人には読みにくい。
5. LLM と組んだ記号の体系（定義番号・記号での呼び名）を、公開文に出さない。本人の発言の中にあっても出さない。用語名で書く。

## 7. 既存の理論を扱うとき

1. 理論の言葉の解説は、言葉ごとに同じ四行の表にする。定義／よくある誤解／Love駆動開発の視点で見た解釈／効く条件。
2. 原典の著者名と年だけを書く。紹介者や、何も付け足していない後続の人の名前は書かない。
3. 原典の言葉を中立な定義として写す前に、その言葉がどんな人の像で書かれているかを見る。理論の理想の像を、本人の見方と結びつけない。
4. 理論の要旨は、調べてから書く。二次資料しか読めないときは複数を照合し、原典を本文で読んだか・二次要約か・記憶かを分けて書く。
5. 既存の理論で、本人の見方を説明しようとしない。並べて見るときは、本人の言葉が立っているところだけを置く。これは論証に使わないという意味で、類推はする（そのために調べている。pjdhiro 2026-11-09）。類推は類推と分かるように書く。
6. 理論との対比は、相手ごとに一ページにする。

## 8. 主題ごとの語

### 重力と空間（Love駆動開発）

見方は `stance-theories.md` の重力・ゼロ・無の行（重力は重力場で歪む。空間も重力場。「重力は力ではない」と言い切らない。「ゼロ」「無」は認知しづらいという意味）。書くときの形：

1. くぼみや井戸の絵は、重力場の形として書く。重力の描き方は理論ごとに違い、どれも一面。
2. 一つの理論に寄せて書くときは、理論を名指しして定義を添える。
3. 「空間」「時空」を、説明のない入れ物の語として使わない。
4. Love と重力の構造の似かたは、重力場のようなものとの関係として見る。
5. 「ゼロ」「無」に、物理の「力がゼロ」を当てはめない。

### 物理の主張

1. 物理の主張は、教科書の事実・研究の一線・Claude の読み替え のどれかを区別して書く。pjdhiro は物理の真偽を判定できないので、この仕分けは Claude が引き受ける。
