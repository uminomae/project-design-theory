# 型 R・型 G の確認（作業の種類ごと）

`corrections.md` の型 R（継ぎはぎで組む）と型 G（読み違い）の「書く前の確認」のうち、決まった作業のときにだけ要る文を、2026-11-10 にここへ分けた（型 K を `corrections-k.md` に分けたのと同じ形。毎回読む分を小さくするため）。文は分ける前のまま。毎回は読まない。その作業を始める前に、当たる節だけを読む。

どの対話でも要る文（冒頭だけで分かるか・初めて読む人に通じるか・pjdhiro に説明や問いを出すときの形、本人の言葉と指示の読み）は、`corrections.md` の表に残してある。繰り返しの記録は `corrections-repeats.md`。

| 節 | いつ読む |
|---|---|
| R1 冒頭と概要 | 読み物の冒頭・概要・まとめを書く・直す前 |
| R2 語とたとえ | 公開文を書く・直す前。部の接続やまとめの文を書く前 |
| R3 参照とリンク | 公開文でほかの章やページを指す前 |
| R5 手作業の頼み方 | pjdhiro に手作業（原典の保存・画面での確かめ など）を頼む前 |
| G3 物理と尺度の語 | 物理の話、脳の働きと時間の話を書く前 |

R4（pjdhiro への説明と問い）と G1・G2（指示の言葉・本人の言葉と定義の読み）は、どの対話でも要るので `corrections.md` に残した。

## R1 冒頭と概要

- 冒頭の概要の箇条を、章の中身を順に説明する文や具体の列挙で埋めていないか。
- 部の接続の段と同じくらい短く、包括的な語で、一言で言える長さか（2026-11-09・Love駆動開発の概要を章立てに合わせたとき、箇条に「細かすぎる」「唐突すぎる。一言で言うならあってる。」）。

## R2 語とたとえ

- サイト特有の語（重力の井戸 など）だけでなく、その読み物が自分で立てたたとえ（「円を重ねる」など）も同じに見る。
- 通じないなら、初出で定義するか、ページ内の説明へリンクする。
- 接続やまとめのように視点を全体へ戻す文では使わず、包括する言葉を先に選んで短く書き、章の題を列挙しない。
- 本文の言い方に合わせることを、正しさの確かめと取り違えない（2026-11-09・Love駆動開発の接続の案に「特殊なたとえを当然のように使うのはやめて」「なるべく短く」。`stance.md` 2-4）。
- 本人がメタ認知の先で到達した感覚の話を、そこへ至る文脈（何を観ていって、どこで感じたものか）なしに、面の一つや畳みの題として出していないか（2026-11-09・Love駆動開発の第四部の「確かめずにつながる安定」・「唐突すぎる」）。

## R3 参照とリンク

- 参照は章題そのままで、行き先の段落へ飛ぶか。
- リンクを貼るだけのところを、文で説明していないか（「〜は、〇〇にあります」でなく、注記の「（参考：〇〇）」で足りる。Love駆動開発の群盲象の段・2026-11-08）。

## R5 手作業の頼み方

- pjdhiro に手作業を頼むときは、チャットのまとめでも Issue の表でも、置き場を指すだけで済ませない。
- 一件ずつ、何のための作業か・開く URL・ページ内で探す語・持ち帰るもの・済んだら何と言えばよいかを、その場で読める形（長ければガイドのページ）で渡したか（2026-11-09・#79 の表に何を見るかが無く「わからない」。2026-11-10・#98 の残りを置き場だけで頼み「これは何？」）

## G3 物理と尺度の語

- 物理の話で「向き」「方向」「逆」と書くとき、増え方の向き（比例か反比例か）と符号（＋か−か）と時間の向きを分けて書いたか。
- 「見込み」「予測」の語でくくるとき、脳の微細な瞬間の働きと、認知できる大きな時間の話を、一つの器に並べていないか（`stance.md` 1-4・2026-11-10）
