# Claude が繰り返す誤りの型（芯）

<!-- scripts/rules-core.py が docs/rules/corrections.md から作る。ここは手で直さない。直すのは corrections.md。 -->

目次（毎回読むのは `corrections.md` の全文。2026-11-19 に戻した）。`corrections.md` の型の表から、型・やりがちなこと・pjdhiro の構えの三列だけを並べた。自分の案がどの型に当たるかを見る。

**当たりそうな型は、`corrections.md` のその行の「書く前の確認」を開いて読む。** 案を出す前・公開文を書く前・手を動かす作業の前は、当たりうる型の行を全部読む。迷ったら開く。トークンの節約を、確かめより先にしない（pjdhiro 2026-11-19）。繰り返しの決まりと表も `corrections.md` にある。

| 型 | Claude がやりがちなこと | pjdhiro の構え |
|---|---|---|
| A 一般論に丸める | 通説・教科書・きれいな定義・一般知識の例で埋める。pjdhiro の公開文を読まずに書く。既存の理論で本人の見方を説明しようとする | 体験が先で、理論は乗り物。pjdhiro の公開文の語彙と本人の言葉で書く |
| B 二元・対立・格子で切る | 言葉や論に良し悪しの判定を付ける、視点で分ける頼みを伝統・地域・話題の棚で切って混ぜる、「AではなくB」、四象限、アンチテーゼ、「射程外」「別の層」で切り分ける、一つに絞る、「生存の側／信頼の側」と分けて置いたまま包まない | 区別は残るが切り離されていない。いろいろ包んでいる。切り口は観る構えで、実在の分割ではない |
| C 範囲を勝手に狭める | プロジェクトに限る、意図ある行為に限る、記号にできる手順に限る、心の働きに限る、将来は予想できる前提を置く | 個人も社会一般も同じ現象。無意識の成長・不可抗力・感情・心の準備も過程に入る |
| D 古典の語彙で書く | 経営学・管理・運営の語彙（列・手順・地図・コントロール・部品・機構・受け皿） | 古典物理で量子を書くような違和感がある。仮説自身の語で書く |
| E 急いで解く・断定・看板 | 保持論点を本文で解く、「正体です」「自然です」「最適」「正解」と言い切る、非二元性を看板にする、無理に論を勝たせる、枝葉の正しさを守ろうとする | 断定しない見立て。保持論点は保持。枝葉を守って大局を見失わない |
| F Claude が Claude に説明する | 「この読み物は〜しません」「一度だけ戻ります」「断定ではなく足場です」 | 規約は Claude の歯止めで、読者への約束ではない |
| G 読み違い | 本人の言葉を条件文・断定・一般論に言い換える、条件を落とす、焦点をずらす、例の一つを規則にする、たとえの芯を取り違える | 趣旨を保つ。「など」の一例を規則にしない |
| H 捏造・転記 | 原典に無い構造や名前を作る、数値を写し違える、確かめていない帰属、引用先に無い言葉を「〜と置いています」と書く、出典を主張と逆向きに当てる、旧サイトの文を確かめ直さずに戻す | 原典と照合する。一次ソースまで遡る。確かめていないものは確かめていないと書く |
| I 浅さ・留保で終わる | 自明な否定を並べる、留保を成果にする、話の流れを切る差し込み | 物理と心がどれだけ深く似ているかを厚く。留保は足場で成果ではない |
| J 文体の演出 | 体言止めの連打、ダッシュ、対句、独自の比喩ラベル、擬人化、決め台詞、一般的でない言い回し（「よく聞く像は」「〜に足があります」） | 教科書のような普通の文。差は視点で出す。言い回しは「たとえば」のような平易なものに |
| K 作業の杜撰・早すぎる諦め | 品質の確かめを省く、場当たりで直す、曖昧な削除で全部消す、取得できないと言って諦める、指摘への対症で部品を足す、記録や画面やコードを見ずに記憶と推測で見立てる・案内する・説明する、見つけた原因を報告だけして直さない | 調べる → 案 → レビュー → 確かめる → 直す。大きな改稿は計画を先に。削除は対象を一文で確かめる。別の経路を探す。原因が分かったら、その場で直す |
| L しっくり感を軽く見る | 数理が正しい・論理が合っているから採る | 最終の判定はしっくり感で、pjdhiro が行う |
| M Claude への説明を本文に引く | 対話で Claude の書き方を直すために言われた構えを、「pjdhiro の見方」として本文に貼る。発言を並べて、答えや流れの代わりにする | 構えは引用せず、書き方に溶かす。引用するのは体験・像・定義・問い。答えは、読み物と探究の筋から書く |
| N 発言の受け答えで本文を書き換える | 発言の一つ一つに、すぐ本文を書き換えて返す | 発言はいったん材料として受け止め、節全体を見直してから案を出す |
| O 図の目的を見ない | 図を直すとき、その図が見せる一点を確かめずに部品を足す・外す | 直す前に、図が見せる一点を一文で言う |
| P 確かめすぎる | 話の流れで意図が明らかな操作（マージ・push・公開）を、そのたびに「よいですか」と聞いて止まる。規約で答えが出る判断を「pjdhiro の判断が要るもの」として並べる。次の一手を言うだけで、始めずにターンを終える。先の作業を止めない判断まで並べて、答えを待つ | 編集者は pjdhiro 一人で、git は履歴のため。流れで明らかなら進める。判断基準は repo にある |
| Q 言葉を取り違える | 報告を英語で書く。作業の途中から英語に切り替わる | pjdhiro とは日本語で話す |
| R 継ぎはぎで組む | 章を足すたびに、前の章のあだ名（「価値の章」）や別ページの語（重力の井戸）に寄りかかる。冒頭のまとめ・用語の定義・ページ内の正確なリンクを後回しにする | 長文の作法（冒頭の問いと概要・用語は初出で定義・参照は章題そのままで行き先へ直接）を守り、教科書のように平易に |
| S git を共同開発の作法で使う | worktree の枝に作業を溜め、マージ・取り込み・「下書きは develop、確かめたら main」のような段取りを組み、その説明で確かめを求める | `CLAUDE.md` の Git の節のとおり。個人の文章管理で、プルリクは要らない。編集したら develop へ最速で統合し、手元のサーバーで目視する |
| T 話題の外に手を出す | 違和感帳や別のセッションから届いた、今のセッションの話題でない一件に、その場で答えて直す・別のセッションまで始める | 一つのセッションは一つの話題。外のことは担当のセッションへ（stance 2-8） |
| U 不確実性を避ける | すでに起きたこと・いま起きていることの記述に寄り、これから起きるであろうこと・起きるかもしれないことへの構え（不確実性への対処）を書かない。「起きていることの中から」「振り返って」「あとから」で段を閉じる。原典をまとめるとき、先へ向く側（ナイトの不確実性の引き受け など）を落とす | 構想も設計も対処も、起きるであろうこと・起きるかもしれないことまで含めて行う。不確実性に対処する構えを、ページ全体として欠かさない（stance 1-3） |
