# 公開してよいかの点検

この repo は公開です。入れたものは、履歴ごと誰でも読めます。消しても履歴には残ります。なので、入れる前に点検します。

## いつ行うか

- 今までの repo から材料（主張・発言・判断・図・コード）を取り込むとき。
- commit のたび。機械の点検は pre-commit で自動に走る。

## 機械の点検

`scripts/publish-check.sh` が、commit しようとしている内容から次のものを探す。

- 手元だけの語の一覧（`.publish-check-terms`）にある語。公開しない名前などを一行に一語で書く。この一覧そのものは公開しないので、`.gitignore` に入れてある。
- 手元のパス（`/Users/…`・`~/…`・区切りが `-` の一時置き場のパス など）。`~/` の形のうち、公開している置き場の決まり（`~/dev/pd/…` ほか）と道具の設定の置き場（`~/.claude/` など）は通す。
- 鍵・トークンの形をした文字列。
- メールアドレス（commit の trailer で使う公開用のものは除く）。
- 非公開になりうる共有のリンク（claude.ai のアーティファクト・共有・チャット・プロジェクトのリンク）。これだけは、止めずに数とファイルを知らせる。確かめ用のページへのリンクを公開の repo に置いてよいかを、pjdhiro がまだ決めていないため（2026-11-10・#111）。
- zip などの書庫は、中のファイルの名前に上の語と形が無いかを見る（中身は開かない）。

当たったら commit は止まる。中身を確かめて、直すか外す。

`~/` のパス・一時置き場のパスは、中身を確かめたうえで、通す一覧（`.publish-check-allow`）に一行足すと通る（共有のリンクの行は、知らせの数から外す）。`ok` は確かめて通したもの、`wait` は pjdhiro の判断を待っているもの（通すが、点検のたびに数を知らせる）。語・鍵・メール・`/Users/` の形は、この一覧では通せない。

当たった出典の書き方は、置き場の名前でなく「何の資料か＋番号」に直す。たとえば、非公開の repo の中の発言の置き場のファイル名は、「pjdhiro の発言集（非公開）S18」と書く。出典の役は残り、点検は通る（2026-11-10・#111）。

手元で一度だけ、次を実行して pre-commit を有効にする。

```bash
git config core.hooksPath .githooks
```

repo 全体を見直すときは次を実行する。手元だけの語の一覧に語を足したときも回す。

```bash
scripts/publish-check.sh --all
```

同じものを `.github/workflows/check.yml` が develop と main で回す。語の一覧は git に無いので、そこで回るのは形の点検だけ。

## main へ送る前の確かめ

`.githooks/pre-push` が、main への push を、送る commit を `bash scripts/publish-main.sh <送る枝>` で見たあとでなければ止める。道具は、一緒に公開される commit・変わるファイル・記録の「main には送っていない」の行を出して、見た印を置く。

- 印は worktree ごとで、送る commit の番号と置いた時刻が入る。push する commit と番号が合い、置いてから 30 分以内のときだけ通る。別のセッションが置いた印では通らない。
- 今の main の先頭より後に書かれた記録に「main には送っていない」の行があると、印は置かれない。その行が自分の送る変更のことでないと確かめてから、`--seen` を付けて走らせ直す。

## ここは仕組みで止まらない

次のものは、フックでも道具でも止まらない。使わない。

- `git commit --no-verify`・`git push --no-verify`：フックそのものが走らない。公開前の点検も、main へ送る前の確かめも通らずに入る。
- GitHub の上での操作（ウェブでの develop から main への merge・`gh pr merge`・`gh api` で枝を書き換える）：手元のフックを通らない。
- クラウドのセッションの commit：`core.hooksPath` は手元の設定で、手元だけの語の一覧も無いので、pre-commit の点検は走らない。入ったあとに `.github/workflows/check.yml` が形の点検（手元のパス・鍵・メール・非公開になりうるリンク・書庫の中の名前）だけを回す。語の点検は手元でしか回らない。
- 道具を走らせて出たものを読まずに送ること：印は「走らせた」ことしか確かめられない。

## 目の点検

機械では見つからないものがある。材料を取り込むときは、次を目で確かめる。

1. 公開されていない場所（非公開の repo・手元のメモ・私的なやりとり）の中身が入っていないか。名前と番号だけなら書いてよい場合があるが、依頼・発言・作業結果・記録の中身は書かない。
2. 個人の情報（本人以外の人の名前・連絡先・私的な事情）が入っていないか。
3. 原典そのもの（論文の PDF・本の長い引用）が入っていないか。原典は書誌と取得先を書く。
4. 今までの repo の調査結果を、確かめ直さずに写していないか。

迷うものは入れずに、pjdhiro に確かめる。
