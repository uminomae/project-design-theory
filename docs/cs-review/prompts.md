# エージェントに頼む文の雛形

cs の全体レビュー（`README.md`）で、エージェントに頼む文。試しの一巡（2026-11-08。D01 数学と D22 経営学）で使った文を、本番で使える形に直した。`{…}` を埋めて使う。

- R は `~/dev/pd/project-design-theory`（本体の checkout）。読むのはここ。原典の PDF はここの手元にしか無い。
- W は、頼む側のセッションの作業場所（worktree なら worktree のパス）。書くのはここ。エージェントが本体の checkout に書こうとすると、フックで止まる（D22 で起きた）。親のセッションが確かめてから develop に入れる。

エージェントは Opus で、バックグラウンドで走らせる（Agent ツールの `model: "opus"`・`run_in_background: true`）。司令塔の親のセッションは Fable 5.1（README「エージェントの分け方」）。

どの頼む文にも、次の四つを入れる。

- 日本語で作業し、日本語で報告すること（型 Q）。
- 書いてよい場所（読むだけか、W の記録のファイル一つだけか）。commit と push はしない。手元の絶対パス（/Users/…）を書かない（公開前の点検で止まる）。
- 材料の在りか。書かないと、探すのに時間の半分を使う（D01 は半分を探すことに使い、在りかを書いた D22 はほとんど要らなかった）。
- 原典の取り方：manifest に OA の URL がある文献は、取ってきて読んでよい（`sources.md` §5）。作業用の一時置き場に置き、repo には入れず、取ったものを報告に書く。手元の `cs/knowledge/raw/` に入れるかは親のセッションが決める。

エージェントの報告は、親のセッションが要の点を二つ三つ確かめ直してから使う（試しの日は、DOI・定義の文・D22 の引用を確かめ直した）。

## 1. 内容の照合（一つの領域）

```
日本語で作業・報告してください。書いてよいのは {W}/cs/evidence/evidence-{Dxx}-{slug}.md の一つだけです（今は再監査待ちの stub。これを置き換える）。ほかのファイルは書き換えず、commit も push もしないでください。読むのは R＝~/dev/pd/project-design-theory です。手元の絶対パス（/Users/…）は記録に書かず、~/dev/… か repo の相対パスで書いてください。
manifest に OA の URL がある文献は、取ってきて読んでかまいません。作業用の一時置き場（$TMPDIR の下に自分用のディレクトリ）に置き、repo には入れず、取ったものを報告に書いてください。PDF は pdftotext で読めます。PMC の全文は NCBI の efetch（db=pmc）か Europe PMC の REST（/fullTextXML）で XML が取れます。出版社や PMC の PDF が自動取得の確認画面を返すときは、別の名乗りで取りに行かず、「ブラウザでの保存が要る」と書いてください。

## やること
単位は「論」。この分野で 10 ほどの論を、一つずつ一次情報で確かめる（README「調査の手順」）。今の報告が取り上げた論から始め、一次情報が見つからない論は照合の状態を書いて残すか、確かめられる論に差し替え、足りない論は足す。一つの論の中で深く照合するのは、(a) 5段階（対立・衝突・統合）との対応、(b) 人名・年・数・書誌、(c) 正本（Love駆動開発・ks・as）や cs のトップが引いている文。報告に出てこない「似た論文」（manifest の [similar-papers]）は、論として足すときだけ使う。

1. すでに集めた原典をベースに、10 ほどの論を決める。ベースは R/cs/knowledge/raw/manifest.md のこの分野の行（`raw-confirmed`・`url-verified` が読める原典、`[similar-papers]` は似た段階モデルの比較対象）、手元の PDF、精読ノート（R/cs/knowledge/source-notes/{Dxx}/・R/pd/wiki/sources/{Dxx}_*）。今の報告が取り上げた論と突き合わせ、集めた原典の無い論は、まず探し、見つからなければ照合の状態を書いて残すか、集めた原典のある論に差し替える。読める原典で 10 に届かなければ、さらに探す（OA・著者の公開版・機関リポジトリ・学術検索の PDF リンク。sources.md §5）。新しく見つけた原典は、manifest に足す行（source_id の案・書誌・取得先・状態）を報告に書く（manifest は書き換えない。司令塔が足す）。論ごとに、今の報告の主張を (a)〜(c) から取り出す。
2. 各主張の根拠の文献を特定し、wiki・source-notes・PDF の有無を書く。
3. 一次情報は、URL があるかダウンロードできるもの（pjdhiro と第三者が確かめられるもの）を探す。manifest に無くても、著者の公開版・機関リポジトリ・OA 版を別の経路で探してよい。各行に確かめ先（URL・DOI）を書く。取ってきた PDF は、先頭が %PDF かと、1 ページ目の書誌（著者・年・題）が狙った文献と一致するかを確かめる（別年・別論文を掴む取り違えが何度も起きている。#53）。手元の PDF も、報告が引く書誌と表紙を突き合わせる（D10 で、手元の PDF が同じ年・同じ誌の別の論文だった）。PMC は DOI から pmcid を引いて取る。PDF があるもの（取ってこられたものを含む）は、本文の該当箇所を読み、ページを控える。写しに誌面の頁番号が無いとき（打ち直し・再録・著者稿・翻訳）は、写しの頁か節の名前で控え、そう書く。著者側の要約版は「要約版」と書き、原本の書籍は未照合とする。翻訳で読んだときは訳者・版・ライセンスを書き、照合の状態に「（訳）」を添える。archive.org などに個人が上げた写しは、読んでよいが「個人が上げた写し。権利は未確認」と性格を添え、それだけで「本文照合済」としない。書籍だけの論は、OA の検索・著者や大学のサイト・機関リポジトリ・学術検索・公開書籍のアーカイブと、著者の論文版・パブリックドメインの古典・CC の翻訳を探して無ければ止め、「未照合（書籍）」と書いて論は残す。ほかの分野の記録（R/cs/evidence/evidence-Dxx-*.md）で本文照合済になっている理論は、読み直さずにその記録を参照して書く。少なくとも 3 本（できれば 6 本以上）。PDF が無く精読ノートしか無いものは「精読ノートのみ」と書き、ノートの引用が主張を支えているかを見る。精読ノートそのものも誤ることがある（D22 で、同じ文献の二枚のノートが食い違い、片方は原典の頁を読んでいなかった）。精読ノートに無いことを、原典に無いことと読まない（D22 の試しの点検で、5 フェーズを「書籍でしか確かめられない」と誤った）。原典を読めたときは、ノートとも照らす。
4. 書誌（著者・年・題・DOI）を、wiki・PDF の表紙・Crossref（https://api.crossref.org/works/{DOI}）で突き合わせる。
5. 当てはめ（その理論を5段階のどこに対応させたか）がこじつけでないかを見る。合うところを増やすより、反例・語が同じだけの対応・藁人形の議論・出典を主張と逆向きに使う所（D22 で、段階の順を否定する Gersick を「裏付け」にしていた）を探す。似ているかどうかの芯は、その理論で対立や衝突が欠かせない形になっているか（README「中心の問い」）。報告が衝突や悪いことを「阻害」「失敗モード」「対象外」として過程の外に置いていないか、衝突（Storming・危機など）を波に当てて縁を接続や選択として読んでいないかも見る（`history.md`「中心の問いの材料」）。衝突の相手は、嫌なこと・悪いことなど良いこと以外のもので、それを過程の外に置かずに包んで進むか。これを原典で確かめる。良いものだけで調和して進むように描いている所は、似ているとは言いにくい。理論が見ている単位の大きさ（微細さ：海の一粒まで見る量子論のように細かいか、母体・出産・子孫のように大きな単位か）は一言添えるが、粗い論も芯があれば似ていると数える（正反合くらいの粗さでもよい）。粗い論で段階の一部が見えないことを反証としない。
6. 日本語版・英語版・プレゼン版・evidence の退避版の間で、数や提唱者が食い違っていないかを見る。英語版とプレゼン版は訳ではなく別々に書かれた文章で、どの段に当てたかまで違うことがある（D22）。少なくとも段の当てはめの表は版ごとに比べる。
7. 誤りの出どころを一行で書く：DR・調べた跡（investigation の phase5〜7）・退避版・テンプレートのどこから来たか（`sources.md` §7-2「誤りの出どころの記録も直す」）。
8. 文章を writing.md と corrections.md の型で見る。代表例を引用付きで数件。
9. README の中心の問いに沿って、一面の表を書く：この分野の論ごとに、何と何が対立し（対立）、どうぶつかり（衝突）、どう包まれ（統合）、何が残ったか（新たな安定）を一行に書き、原典で確かめた度合いと論の微細さを添える。原典に無い対立・衝突を補って作らない。統合に至らなかった例（報告が「失敗」「阻害」「対象外」とした所を含む）も行として書き、どう終わったか（片方が勝って波に留まる・場に戻る、分裂・消散・固着・凍結・暴走など。悪い統合も統合として書く）と、至るか至らないかの分かれ目（閾値・条件）が原典に書かれていればそれも書く。分野に合否は付けない。

## 書くもの
{W}/cs/evidence/evidence-{Dxx}-{slug}.md を書く（README「記録の形」）。この md はそのまま公開され、cs の UI から読まれる（`cs/evidence/reviewed.json` に行を足すと、トップの「30領域調査報告」がこの md を先に読む。足すのは司令塔）。文は R/docs/rules/writing.md に従い（教科書のような普通の文・演出しない・断定しない・一文に一つのこと・文末は「です・ます」）、冒頭に文責が Claude であることを書く。並びは次のとおり。
- 冒頭：この分野で見えた対立・衝突・統合を数文で。文責。退避版（R/cs/evidence/archive/pre-rerun-20260407/evidence/）への history のリンク。
- 一面の表：論ごとに一行（論・対立・衝突・統合／新たな安定、または統合に至らずにどう終わったか・論の微細さ・照合の状態）。
- 論ごとの節（10 ほど）：要旨、一次情報の確かめ先（URL・DOI・manifest の行）と読んだ頁、照合の状態（sources.md §3 の四つ：本文照合済・要旨照合済・二次資料のみ・未照合）、対立・衝突・統合の読み（原典に書いてあることと Claude の読み替えを分ける）、今の報告から直したこと（誤り・言い過ぎ・取り違え・帰属違い・付け足しを、報告の行と一緒に）。
- 公開報告の点検のまとめ：版の間の食い違い、テンプレート由来の表示、誤りの出どころ、文体。
- 判断が要るもの（あれば。stance.md で答えを予想して添える）。
- 新しく見つけた原典（台帳に足す案）：表で、番号は台帳と同じ形（`D21-S17` のように）で書く。司令塔が台帳に足す。機械の点検で「台帳に無い行」と出ても、番号を崩さない（2026-11-08・D21）。
- 新しく見つけた原典（台帳に足す案の表。source_id の案・書誌・取得先・状態）。
- 手順について分かったこと（短く）。
```

### 領域ごとの注意

- 数学・物理・複雑系：物理と数学の主張に、教科書・研究の一線・Claude の読み替えのどれかを添える（`sources.md` §6）。数学の記述の正しさは Claude が引き受ける。仏語の古い論文（Bull. SMF・J. Math. Pures Appl.）は Numdam で原文が OA。AMS の古い巻は無料だが自動取得に確認画面を返す。数学の原典は対立・衝突の語を使わないので、一面の表は原典の構造を先に書き、中心の問いへの読み替えと分ける（2026-11-09・D01）。物理の有料の原論文は、著者のノーベル講演（nobelprize.org）か arXiv の著者稿で「著者のまとめ直し」「著者稿」として読める。PDF の頁と誌面の頁の対応は、頁番号を一つ確かめてから控える（講演で 1 頁ずれた。2026-11-09・D02）。 複雑系の原典は、分かれ目の上と下で何が起きるかを式や数で書くので、至らない形（減衰・吸収状態・閉じない集まり・均一のまま・凍結）はそこから拾う。有料の原論文は、同じ分野の総説（Dickman ら 2000・Watkins ら 2016・Newman 2003）でも論の芯に当たれる。上げた人の分からない写し（ResearchGate・Zenodo）は個人の写しと同じ扱い。台帳が OA と書く取得先が落ちているとき（OSTI の 502）は、確認画面と分けて書く（2026-11-09・D29）。 化学（D03）：有料の原論文はノーベル講演（Semenov・Hinshelwood・Lehn）と PMC の著者稿で読めるが、講演が論の確かめ先になるとは限らない（Flory の講演はゲル化を扱わない）。政府機関の英訳（NACA の技術翻訳）はパブリックドメインで本文照合済（訳）。学会のサイトの写し（Wayback の記録を含む）は大学のサイトの写しと同じ扱い。PMC の efetch の XML が要旨だけのときは、PMC の記事の頁（HTML）で全文が読める。済んだ分野が未照合とした原典を開けたときは、報告に書く（済んだ分野の記録は司令塔が上げる）（2026-11-09・D03）。
- 経営学・心理学・社会学など、pjdhiro が理論との距離を記録している分野：stance-theories.md の表（期待・信頼・心理的安全性・内発的動機・価値・創造・経営・エフェクチュエーション）と writing.md §7（既存の理論を扱うとき）を先に読む。報告が理論の理想の像を、pjdhiro の見方や5段階と結びつけていないかを見る。報告が理論を「強い対応」「最も精密」と持ち上げていないか、二つの論理を5段階の両端に分けて置いていないか（D22 で、因果論理を束、エフェクチュエーションを場に置いていた。型 B）も見る。調べた跡（phase5〜7）が欠損・抱持を持ち込んでいないか（報告に持ち込まない、は今も使う旧い規則）も見る。
- 生物学（進化生物学・生命科学・薬学・農学）：生物学の主張にも教科書・研究の一線・Claude の読み替えを添える（争いの多い分野なので研究の一線が多い）。有料の原論文は著者の後の総説（PNAS・PMC）で読める。PNAS は PMC の XML を出さないので PMC の HTML、eLife は公開 API の JSON で読む。PMC の HTML を続けて取ると reCAPTCHA になる（確認画面として書く）。手元の写しの出どころは、Wayback と同じサイトの写しとバイト単位で比べて確かめる（Eldredge & Gould が出版社の教科書サイトの写しだった）。原典は競り合いで消えるもの（絶滅・除去・偶然の消失）を中心に書くので、至らない形はそこから拾う（2026-11-09・D04）。
- 地球科学・天文学（D05・D06）：原典は、ためる力と抑える力の兼ね合い（応力と強さ・浮力と抵抗・正と負のフィードバック・促す要因と妨げる要因）と、分かれ目の両側で何が起きるかを書く。至らない形はそこから拾う（破壊が止まる・事象が育たない・マグマが止まる・地層が残らない・回復の間に消える）。報告の引く原論文は Nature・Science・AGU（Wiley）・Elsevier が多く、自動取得はどれも 403 かログインの画面（AGU の 24 か月後の無料も Wiley の自動取得では 403）。同じ論の後の総説と、至らない形を題にした論文（「失敗した噴火」・絶滅のあとの回復）を大学の授業の頁・PMC・著者の所属の学科のサイトで探すと本文に当たれる。パブリックドメインの政府・委員会の報告（Reid 1910）は Internet Archive の OCR の文字で読む。PMC の efetch の XML は PNAS の古い論文で要旨だけなので記事の頁（HTML）で読む。頼む文に書く PMC の番号は、取ってから題で確かめる（D05 で一つ隣の論文を書いていた）（2026-11-09・D05）。 天文学の古い論文（ApJ・MNRAS・A&A）は ADS の誌面の走査で自動取得できる（403 は無かった）が、1970 年代の A&A・MNRAS の一部と仏語の誌は文字の層が無いので、頁の画像にして読んだ頁を控え「走査の画像で読んだ」と書く。書籍だけの論は同じ著者の論文版、壁の原論文は NASA の助成の報告（NTRS）に付いた誌面で読めることがある。報告の帰属は、後の教科書の像を古い原典に帰していないか、原典の年とその論文が使った語で確かめる（2026-11-09・D06）。
- 人文系（哲学・宗教学・伝統知・文芸学など）：原典が書籍で、PDF が無いものが多い。「精読ノートのみ」「二次資料のみ」を正直に書き、取得できないことを理由に判定を上げない。東洋の像は、原典の文脈で照合する（writing.md §2-9）。書籍だけの論でも、著者自身の論文版が機関リポジトリで OA のことがある（ターナーの 1974 年の Rice University Studies の論文。2026-11-09・D25）。パブリックドメインの仏語の古典は、Gallica が自動取得に確認画面を返すので、英訳で読み、原文の頁は未確認と書く。大学の授業のサイトに置かれた写しの扱いは README「規約で決めたこと」2026-11-09 の行。
