# エージェントに頼む文の雛形

cs の全体レビュー（`README.md`）で、エージェントに頼む文。試しの一巡（2026-11-08。D01 数学と D22 経営学）で使った文を、本番で使える形に直した。`{…}` を埋めて使う。30 分野の記録は 2026-11-09 にそろったので、いまこの雛形を使うのは、済んだ記録を回し直すとき（照合し直し・比べ）。

- R は `~/dev/pd/project-design-theory`（本体の checkout）。読むのはここ。原典の PDF はここの手元にしか無い。
- W は、頼む側のセッションの作業場所（worktree なら worktree のパス）。記録を書くのはここ。親のセッションが確かめてから develop に入れる。
- 頼む文には W を必ず書く。worktree のセッションでは、Write・Edit のツールで本体の checkout に書こうとすると、アプリの仕組みが止める（repo の hook ではない。`.claude/settings.json` に、書き込みを止める hook は無い）。Bash からの書き込み（道具の追記・`cp`）は止まらないので、「止まるから大丈夫」と読まない（2026-11-10 に実物で確かめた）。

エージェントは Opus で、バックグラウンドで走らせる（Agent ツールの `model: "opus"`・`run_in_background: true`。effort は「1. 内容の照合」が `"high"`、ほかは `"medium"`）。司令塔の親のセッションは Fable（その時の最新）。モデルと effort の決め、替えるときの比べ方と、その結果（照合を high にした農学・生態学の比べ）は、README「エージェントの分け方」（2026-11-10）。

どの頼む文にも、次の五つを入れる。

- 日本語で作業し、日本語で報告すること（型 Q）。
- 書いてよい場所。読むだけの仕事か、次の三つだけか（正はスキル `find-source`「書いてよい場所」。as の頼む文も同じ）：W の記録のファイル一つ／原典を探す道具（`scripts/find-source.sh`）が自分で追記する、本体の台帳（`cs/knowledge/raw/find-ledger.md`）と止まるホストの一覧（`.cache/raw/find-hosts.tsv`）／取った原典の PDF（道具の `fetch --out` で本体の `cs/knowledge/raw/` へ。道具を通さずに取ったものは `$TMPDIR` の下）。二つ目と三つ目は git の外。commit と push はしない。手元の絶対パス（/Users/…）を記録に書かない（公開前の点検で止まる）。
- 材料の在りか。書かないと、探すのに時間の半分を使う（D01 は半分を探すことに使い、在りかを書いた D22 はほとんど要らなかった）。
- 原典の取り方：決まりは `sources.md` §5、道具の使い方はスキル `find-source`。頼む文には、そのスキルを Read して従うことを書く（雛形に入れてある）。原典の台帳（`manifest.md`。公開）に行を足すのは親のセッション。
- 頼む文に書く書誌（DOI・題・巻号）は、司令塔が Crossref で照らしてから書く（型 H）。

エージェントの報告は、親のセッションが要の点を二つ三つ確かめ直してから使う（試しの日は、DOI・定義の文・D22 の引用を確かめ直した）。

## やること
単位は「論」。この分野で 10 ほどの論を、一つずつ一次情報で確かめる（README「調査の手順」）。今の報告が取り上げた論から始め、一次情報が見つからない論は照合の状態を書いて残すか、確かめられる論に差し替え、足りない論は足す。一つの論の中で深く照合するのは、(a) 5段階（対立・衝突・統合）との対応、(b) 人名・年・数・書誌、(c) 正本（Love駆動開発・ks・as）や cs のトップが引いている文。報告に出てこない「似た論文」（manifest の [similar-papers]）は、論として足すときだけ使う。

1. すでに集めた原典をベースに、10 ほどの論を決める。ベースは R/cs/knowledge/raw/manifest.md のこの分野の行（`raw-confirmed`・`url-verified` が読める原典、`[similar-papers]` は似た段階モデルの比較対象）、手元の PDF、精読ノート（R/cs/knowledge/source-notes/{Dxx}/・R/pd/wiki/sources/{Dxx}_*）。今の報告が取り上げた論と突き合わせ、集めた原典の無い論は、まず探し、見つからなければ照合の状態を書いて残すか、集めた原典のある論に差し替える。読める原典で 10 に届かなければ、さらに探す（OA・著者の公開版・機関リポジトリ・学術検索の PDF リンク。sources.md §5）。新しく見つけた原典は、manifest に足す行（source_id の案・書誌・取得先・状態）を報告に書く（manifest は書き換えない。司令塔が足す）。論ごとに、今の報告の主張を (a)〜(c) から取り出す。
2. 各主張の根拠の文献を特定し、wiki・source-notes・PDF の有無を書く。
3. 一次情報は、URL があるかダウンロードできるもの（pjdhiro と第三者が確かめられるもの）を探す。manifest に無くても、著者の公開版・機関リポジトリ・OA 版を別の経路で探してよい。各行に確かめ先（URL・DOI）を書く。取ってきた PDF は、先頭が %PDF かと、1 ページ目の書誌（著者・年・題）が狙った文献と一致するかを確かめる（別年・別論文を掴む取り違えが何度も起きている。#53）。手元の PDF も、報告が引く書誌と表紙を突き合わせる（D10 で、手元の PDF が同じ年・同じ誌の別の論文だった）。PMC は DOI から pmcid を引いて取る。PDF があるもの（取ってこられたものを含む）は、本文の該当箇所を読み、ページを控える。写しに誌面の頁番号が無いとき（打ち直し・再録・著者稿・翻訳）は、写しの頁か節の名前で控え、そう書く。著者側の要約版は「要約版」と書き、原本の書籍は未照合とする。翻訳で読んだときは訳者・版・ライセンスを書き、照合の状態に「（訳）」を添える。archive.org などに個人が上げた写しは、読んでよいが「個人が上げた写し。権利は未確認」と性格を添え、それだけで「本文照合済」としない。書籍だけの論は、OA の検索・著者や大学のサイト・機関リポジトリ・学術検索・公開書籍のアーカイブと、著者の論文版・パブリックドメインの古典・CC の翻訳を探して無ければ止め、「未照合（書籍）」と書いて論は残す（未照合の括弧の中の語は sources.md §3 の 7 の六つ）。ほかの分野の記録（R/cs/evidence/evidence-Dxx-*.md）で本文照合済になっている理論は、読み直さずにその記録を参照して書く。少なくとも 3 本（できれば 6 本以上）。PDF が無く精読ノートしか無いものは「二次資料のみ（精読ノート）」と書き（「精読ノートのみ」とは書かない。点検で落ちる）、ノートの引用が主張を支えているかを見る。精読ノートそのものも誤ることがある（D22 で、同じ文献の二枚のノートが食い違い、片方は原典の頁を読んでいなかった）。精読ノートに無いことを、原典に無いことと読まない（D22 の試しの点検で、5 フェーズを「書籍でしか確かめられない」と誤った）。原典を読めたときは、ノートとも照らす。
4. 書誌（著者・年・題・DOI）を、wiki・PDF の表紙・Crossref（https://api.crossref.org/works/{DOI}）で突き合わせる。
5. 当てはめ（その理論を5段階のどこに対応させたか）がこじつけでないかを見る。合うところを増やすより、反例・語が同じだけの対応・藁人形の議論・出典を主張と逆向きに使う所（D22 で、段階の順を否定する Gersick を「裏付け」にしていた）を探す。似ているかどうかの芯は、その理論で対立や衝突が欠かせない形になっているか（README「中心の問い」）。報告が衝突や悪いことを「阻害」「失敗モード」「対象外」として過程の外に置いていないか、衝突（Storming・危機など）を波に当てて縁を接続や選択として読んでいないかも見る（`history.md`「中心の問いの材料」）。衝突の相手は、嫌なこと・悪いことなど良いこと以外のもので、それを過程の外に置かずに包んで進むか。これを原典で確かめる。良いものだけで調和して進むように描いている所は、似ているとは言いにくい。理論が見ている単位の大きさ（微細さ：海の一粒まで見る量子論のように細かいか、母体・出産・子孫のように大きな単位か）は一言添えるが、粗い論も芯があれば似ていると数える（正反合くらいの粗さでもよい）。粗い論で段階の一部が見えないことを反証としない。
6. 日本語版・英語版・プレゼン版・evidence の退避版の間で、数や提唱者が食い違っていないかを見る。英語版とプレゼン版は訳ではなく別々に書かれた文章で、どの段に当てたかまで違うことがある（D22）。少なくとも段の当てはめの表は版ごとに比べる。
7. 誤りの出どころを一行で書く：DR・調べた跡（investigation の phase5〜7）・退避版・テンプレートのどこから来たか（`sources.md` §7-2「誤りの出どころの記録も直す」）。
8. 文章を writing.md と corrections.md の型で見る。代表例を引用付きで数件。
9. README の中心の問いに沿って、一面の表を書く：この分野の論ごとに、何と何が対立し（対立）、どうぶつかり（衝突）、どう包まれ（統合）、何が残ったか（新たな安定）を一行に書き、原典で確かめた度合いと論の微細さを添える。原典に無い対立・衝突を補って作らない。統合に至らなかった例（報告が「失敗」「阻害」「対象外」とした所を含む）も、原典の本文を読めた論なら行として書き、どう終わったか（片方が勝って波に留まる・場に戻る、分裂・消散・固着・凍結・暴走など。悪い統合も統合として書く）と、至るか至らないかの分かれ目（閾値・条件）が原典に書かれていればそれも書く。分野に合否は付けない。一面の表に置くのは、本文照合済の論だけ（下の「書くもの」）。

## 書くもの
{W}/cs/evidence/evidence-{Dxx}-{slug}.md を書く（README「記録の形」）。この md はそのまま公開され、cs の UI から読まれる（`cs/evidence/reviewed.json` に行を足すと、トップの「30領域調査報告」がこの md を先に読む。足すのは司令塔）。文は R/docs/rules/writing.md に従い（教科書のような普通の文・演出しない・断定しない・一文に一つのこと・文末は「です・ます」）、冒頭に文責が Claude であることを書く。書き終えたら node scripts/check-cs-evidence.mjs <記録のパス> を走らせ、落ちた所を直してから報告する（何を見るかは README「記録の品質の点検」）。

本文（frontmatter の下）には、分野や原典の記号（D21・D21-S17 など）と、repo のパスやファイル名（pjdhiro/assets/…・cs/knowledge/…・docs/…・精読ノートや wiki のファイル名・手元の PDF の保存名・*.md）を書かない。分野は名前で、原典は著者・年・題で書く。台帳との対応は「台帳に行がある」「台帳の「著者 年」の行」、精読ノートは「精読ノート「著者 年」」、wiki は「wiki の頁「著者 年」」、手元のファイルは「手元の PDF」、今の報告は「「30 領域調査報告」の〈分野〉の日本語版」、規約は「調べ方の規約 §5-8」のように書く。リンクの行き先（`[経営学の記録](evidence-D22-business-management.md)` の括弧の中）と URL は書いてよい。機械の点検（`scripts/check-cs-evidence.mjs` の 10）が止める（writing §6-3・§6-5。2026-11-09）。
