# エージェントに頼む文の雛形

cs の全体レビュー（`README.md`）で、エージェントに頼む文。試しの一巡（2026-11-08。D01 数学と D22 経営学）で使った文を、本番で使える形に直した。`{…}` を埋めて使う。

- R は `~/dev/pd/project-design-theory`（本体の checkout）。読むのはここ。原典の PDF はここの手元にしか無い。
- W は、頼む側のセッションの作業場所（worktree なら worktree のパス）。書くのはここ。エージェントが本体の checkout に書こうとすると、フックで止まる（D22 で起きた）。親のセッションが確かめてから develop に入れる。

どの頼む文にも、次の四つを入れる。

- 日本語で作業し、日本語で報告すること（型 Q）。
- 書いてよい場所（読むだけか、W の記録のファイル一つだけか）。commit と push はしない。手元の絶対パス（/Users/…）を書かない（公開前の点検で止まる）。
- 材料の在りか。書かないと、探すのに時間の半分を使う（D01 は半分を探すことに使い、在りかを書いた D22 はほとんど要らなかった）。
- 原典の取り方：manifest に OA の URL がある文献は、取ってきて読んでよい（`sources.md` §5）。作業用の一時置き場に置き、repo には入れず、取ったものを報告に書く。手元の `cs/knowledge/raw/` に入れるかは親のセッションが決める。

エージェントの報告は、親のセッションが要の点を二つ三つ確かめ直してから使う（試しの日は、DOI・定義の文・D22 の引用を確かめ直した）。

## やること
全部の主張を同じ深さで照合しなくてよい（README「網羅しない」）。深く照合するのは、(a)「強い」とした5段階との対応、(b) 人名・年・数・書誌、(c) 正本（Love駆動開発・ks・as）や cs のトップが引いている文。報告に出てこない「似た論文」（manifest の [similar-papers]）は対象にしない。

1. 公開報告（日本語）の主張を、(a)〜(c) から一行ずつ取り出す（15 行まで）。
2. 各主張の根拠の文献を特定し、wiki・source-notes・PDF の有無を書く。
3. 一次情報は、URL があるかダウンロードできるもの（pjdhiro と第三者が確かめられるもの）を探す。manifest に無くても、著者の公開版・機関リポジトリ・OA 版を別の経路で探してよい。各行に確かめ先（URL・DOI）を書く。取ってきた PDF は、先頭が %PDF かと、1 ページ目の書誌（著者・年・題）が狙った文献と一致するかを確かめる（別年・別論文を掴む取り違えが何度も起きている。#53）。PMC は DOI から pmcid を引いて取る。PDF があるもの（取ってこられたものを含む）は、本文の該当箇所を読み、ページを控える。少なくとも 3 本。PDF が無く精読ノートしか無いものは「精読ノートのみ」と書き、ノートの引用が主張を支えているかを見る。精読ノートそのものも誤ることがある（D22 で、同じ文献の二枚のノートが食い違い、片方は原典の頁を読んでいなかった）。原典を読めたときは、ノートとも照らす。
4. 書誌（著者・年・題・DOI）を、wiki・PDF の表紙・Crossref（https://api.crossref.org/works/{DOI}）で突き合わせる。
5. 当てはめ（その理論を5段階のどこに対応させたか）がこじつけでないかを見る。合うところを増やすより、反例・語が同じだけの対応・藁人形の議論・出典を主張と逆向きに使う所（D22 で、段階の順を否定する Gersick を「裏付け」にしていた）を探す。似ているかどうかの芯は、その理論で対立や衝突が欠かせない形になっているか（README「中心の問い」）。衝突の相手は、嫌なこと・悪いことなど良いこと以外のもので、それを過程の外に置かずに包んで進むか。これを原典で確かめる。良いものだけで調和して進むように描いている所は、似ているとは言いにくい。理論が見ている単位の大きさ（微細さ：海の一粒まで見る量子論のように細かいか、母体・出産・子孫のように大きな単位か）は一言添えるが、粗い論も芯があれば似ていると数える（正反合くらいの粗さでもよい）。粗い論で段階の一部が見えないことを反証としない。
6. 日本語版・英語版・プレゼン版・evidence の退避版の間で、数や提唱者が食い違っていないかを見る。英語版とプレゼン版は訳ではなく別々に書かれた文章で、どの段に当てたかまで違うことがある（D22）。少なくとも段の当てはめの表は版ごとに比べる。
7. 誤りの出どころを一行で書く：DR・調べた跡（investigation の phase5〜7）・退避版・テンプレートのどこから来たか（`sources.md` §7-2「誤りの出どころの記録も直す」）。
8. 文章を writing.md と corrections.md の型で見る。代表例を引用付きで数件。
9. README の中心の問いに沿って、一面の表を書く：この分野の論ごとに、何と何が対立し（対立）、どうぶつかり（衝突）、どう包まれ（統合）、何が残ったか（新たな安定）を一行に書き、原典で確かめた度合いと論の微細さを添える。原典に無い対立・衝突を補って作らない。分野に合否は付けない。

## 書くもの
{W}/docs/cs-review/{Dxx}.md を、D01.md・D22.md と同じ形で書く（冒頭の要約・一面の表・点検の表・文体・判断が要るもの・手順について分かったこと）。点検の表の列は、場所・主張・根拠の文献・照合の状態・ページ・判定（一致／言い過ぎ／取り違え／帰属違い／付け足し／未判定）・重さ・直し案。照合の状態は sources.md §3 の四つ（本文照合済・要旨照合済・二次資料のみ・未照合）で書く。
